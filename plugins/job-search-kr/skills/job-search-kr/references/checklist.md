# 기본 검토 점검표

SKILL.md 「서류 문구의 필수 과정」 ⑥ 작문 심사, ⑦ 사실·합격 심사, ⑧ 재심사와 마감의 순서로 묶은 표다. 인사 담당자(기본 검토)가 판정하고, 메인 대화도 반영 뒤 재확인과 검토 에이전트를 부를 수 없을 때 이 표를 쓰며, [review.md](review.md) 「직접 확인」도 이 표가 겸한다. 출력 형식은 `agents/job-reviewer.md` 「돌려줄 것」에 있다.

항목마다 ✓(통과) 또는 !(고칠 것)로 판정한다. 점수와 숫자 기준은 쓰지 않는다. 「확인 필요」로 적힌 기준의 처리는 [panel/공통.md](panel/공통.md) 「확인 필요 처리」를 따른다. 규칙의 원본은 [writing-common.md](writing-common.md)다.

「본 대화」 열의 ●는 메인 대화가 검토 에이전트를 부르기 전에 직접 확인하는 항목이다(24번 재판정은 ⑧에서 바뀐 칸을 재판정에 맡기기 전에 한다). ●가 없는 항목은 에이전트가 판정하고 메인 대화는 반영 뒤 재확인과 에이전트를 부를 수 없을 때만 확인한다. 「본 대화 전용」 항목(11, 16, 25)은 에이전트가 판정하지 않는다.

## ⑥ 작문 심사: 읽히는가

이력서·경력기술서의 기본 검토에서는 인사 담당자가 이 묶음도 판정한다. 자소서는 채용 서류 전문가와 국어 전문가가 먼저 심사하므로([review.md](review.md) 「⑥ 작문 심사와 칸 재작성」) 반영 뒤 재확인에 쓴다. 문체 판단은 [style-essay.md](style-essay.md)를 따른다.

| 항목 | ✓ 조건 | 본 대화 |
|---|---|---|
| 1 절차 대조 | 배정표가 있는 서류(자소서)에서, 칸마다 배정표의 칸의 메시지와 핵심 장면이 초안에 보이고, 사례가 배정표가 고른 카드에서 왔으며, 업계 표현이 용어표에서 왔다. 자소서와 지원서 문항(서술형 양식 칸 포함)은 `작성기록.md`에 ①~④ 기록이 있다. 이력서와 경력기술서는 작성기록을 두지 않으므로 이 조건으로 떨어뜨리지 않는다. 아니면 다듬지 않고 처음부터 다시 쓰게 한다 | ● |
| 2 결론 먼저 | 보고서형 서류(이력서, 경력기술서)에 적용한다. 칸과 문단의 첫 문장이 답이고 한 번 읽어 바로 읽힌다. 이야기체 도입이 없다([style-essay.md](style-essay.md) 「2. 보고서형 문체」). 자소서는 이 조건 대신 [style-essay.md](style-essay.md) 「1. 자소서 문체」로 판정한다 | |
| 3 읽기 | 「문체」의 문장 연결을 지켰다(앞 문장에서 이어지는 이유를 댈 수 있고, 마지막 문장 규칙을 따른다). 문단이 둘 이상인 칸은 「문체」의 문단 연결을 지켰다(다음 문단 첫 문장이 앞 문단이 세운 것을 받고, 칸 전체를 꿰는 한 줄이 있다). 같은 길이·같은 구조의 나열이 없다 | ● |
| 4 칸 용도 | 칸마다 묻는 것에만 답한다. 포부를 묻지 않는 칸에 입사 후 문단·다짐이 없고, 그 칸의 마지막 문장은 「문체」의 문장 연결을 따른다. 문단마다 칸 안의 역할이 있고, 자소서 문항이면 문단 순서가 배정표 「유형과 문단 역할」 열과 [essay-kr.md](essay-kr.md) 「문항 유형」 표의 그 유형 구조를 따른다(「칸 용도」) | ● |
| 5 소제목 | 소제목을 쓸지가 [essay-kr.md](essay-kr.md) 「소제목과 문장」의 칸별 판단과 맞고, 소제목이 없는 칸은 첫 두 문장이 요지를 맡는다. 소제목이 있으면 칸마다 그 회사가 확인하고 싶은 사실 하나(공고의 필수·높음 요건이나 배정표의 회사 사실에 닿는 것)를 담고, 한 번 읽어 무엇이 어떻게 됐는지 읽힌다. [essay-kr.md](essay-kr.md) 「소제목과 문장」의 쓰지 않는 것을 지켰다 | |
| 6 표현 | 금지 표현, AI 문체 신호, 「서류에 쓰지 않는 것」(내부 프로젝트 코드·과제 번호·사내 관리번호 같은 사내 식별자, 내부 문제 등)이 없다. 경력 줄은 [writing-common.md](writing-common.md) 「경력 줄 기준」을 지킨다(「줄 수」는 관례이고 판정 기준이 아니다) | ● |
| 7 회사 맞춤 | 치환 시험을 통과한다. 입사 후 문장은 「칸 용도」가 허용하는 칸에만 있고, 그 팀의 과제에 닿는다. 입사 후 포부는 회사 자료로 확인하지 않은 실무 계획이 아니라 경험에서 온 방식과 회사 사업에 붙은 방향으로 쓰였다([essay-kr.md](essay-kr.md) 「입사 후 포부」) | ● |
| 8 다른 지원자 시험 | 같은 직무의 다른 지원자가 쓰면 성립하지 않는다([essay-kr.md](essay-kr.md) 「세 가지 시험」) | ● |
| 9 키워드 | 「키워드 반영률」의 표시와 배치를 따랐다. 공고 핵심 키워드가 근거 문장과 함께 들어갔다 | ● |
| 10 지원 업계의 말 | 지원 회사 사람이 읽고 바로 아는 말이다. 업종이 다른 본업 용어와 기능 이름·처리 단계 같은 세부는 용어표의 짝으로 바뀌었거나 면접 예상 질문 표에 있다. 경험 문장이 직무 프로필 「업무 방식」대로 읽힌다: 무엇을 어떤 기준으로 판단했는지가 있고, 업계가 일하는 순서와 맞으며, 프로필 사실과 맞는 용어표 표현을 썼고, 판정 「없음」 표현으로 경험을 주장하지 않는다(「지원 업계의 말」) | |
| 11 이력서 형식 (본 대화 전용) | 이력서는 [resume-kr.md](resume-kr.md) 「이력서 항목」·「ATS」를 지켰다 | ● |

## ⑦ 사실·합격 심사: 믿을 수 있고 뽑고 싶은가

카드와 프로필을 먼저 대조하고 판정한다([panel/공통.md](panel/공통.md) 「카드와 프로필 먼저 대조」).

| 항목 | ✓ 조건 | 본 대화 |
|---|---|---|
| 12 수치 | 경력 항목마다 결과를 받치는 수치나 대체 근거가 있어 한 일만 적고 끝난 항목이 없고, 자소서 칸의 수치는 그 칸의 메시지를 증명한다. 수치가 없는 결과에는 확인한 방법이 붙어 있다(「수치」) | |
| 13 경험 카드 | 사례마다 칸의 메시지를 받치는 판단, 그 근거, 확인한 변화가 문장에 보인다. 받칠 사실이 카드에 없으면 그 주장을 뺀다 | |
| 14 의도 대조 | 사례 문장이 경험 카드(`profile/stories/`)의 「⑤ 사용자의 말」과 어긋나거나 「⑦ 경계」에 적힌 쓰지 않을 것·이렇게 읽히면 안 되는 것으로 읽히지 않는다. 어긋나면 !이고 문장을 수정한다([panel/공통.md](panel/공통.md) 「의도 대조」) | |
| 15 사실 | 수치·범위·주어가 프로필과 맞는다. 추산 수치에는 「약」이 있고 「본인 추산」 같은 출처 표기는 없다(「추산값 추천」). 회사명·직무명이 공고와 같다. 블라인드 채용이면 학교명·출신지·가족 관계가 드러나지 않는다. 제출본이면 빈칸과 `[확인 필요]`·`[수치 확인 필요]` 표시가 없다. 「사실 대조」의 항목을 모두 맞췄다 | ● |
| 16 기술란 근거 (본 대화 전용) | 기술·도구란의 항목마다 그 기술을 쓴 곳이 경력기술서 「사용 기술·도구」 칸이나 프로젝트 줄에 있다. 없으면 빼거나 쓴 곳을 밝힌다 | ● |
| 17 공고 요건 | 필수 요건(공고가 지원 자격·필수 요건으로 적은 것. 우대 사항은 들지 않는다) 가운데 프로필에 근거가 있는 요건마다 대응하는 근거 문장이 있다. 빠진 요건은 넣을 자리를 정한다. 근거가 프로필에 없는 요건은 서류에 격차 문장으로 쓰지 않고 근거 칸에 「면접 준비로」라고 적는다. 격차의 처리는 [strategy.md](strategy.md) 「정할 것」을 따른다(칸의 질문이 그 요건을 직접 물으면 그 칸에서 답한다) | ● |
| 18 전략 | 지원 폴더에 전략.md가 있으면, 서류가 「내 위치」의 지원 구분과 보일 모습대로 읽히고, 「앞세울 것」의 각도가 칸의 결론이나 사례 선택에 드러나며, 지원동기 칸은 사용자가 고른 「지원동기 각도」로 쓰였고 먼저 제안받은 포지션이면 이 회사를 골랐다고 쓰지 않았으며([essay-kr.md](essay-kr.md) 「지원동기」 6), 「덮을 것」의 답할 방향과 부딪치는 문장이 없다([strategy.md](strategy.md) 「정할 것」). 전략.md가 없으면 판정하지 않는다 | |
| 19 의심 문장 | 채용 담당자가 의심할 문장이 없다. 절대 표현(「없어졌다」, 「0건」, 「모두」)에는 확인 방법이 붙어 있다. 팀·시스템·협력사의 성과와 본인 기여가 구분된다. 격차 문장은 칸의 질문이 직접 물을 때만 있고(17번, [strategy.md](strategy.md) 「정할 것」), 그런 칸과 약점을 묻는 칸의 답도 탈락 사유 목록처럼 읽히지 않는다 | |
| 20 미끼와 1분 설명 시험 | 미끼 문장이 있고, 1분 안에 설명하지 못할 위험 문장이 없다(「1분 설명 시험」) | ● |
| 21 이직 서사·공통 축 | 서류가 프로필 「자기 이해」의 이직 서사(떠나는 이유, 가져가는 경험, 왜 이 산업과 직무인지)와 어긋나지 않고, 공통 축 한 줄이 칸마다 다른 역량으로 드러나며 칸끼리 같은 사람을 가리킨다. 이직 사유를 쓰지 않는 서류(이력서, 경력기술서)에서는 판정하지 않는다 | |
| 22 전체 인상 시험 | 칸을 모두 이어 읽은 인상이 지원 직무의 사람이고, 프로필 「자기 이해」의 인상 줄이 있으면 그것과 어긋나지 않는다. 다루기 어렵다·드세다로 읽히거나 한 종류의 일에 쏠려 다른 직무의 사람으로 읽히면 !이다([essay-kr.md](essay-kr.md) 「세 가지 시험」) | |
| 23 뽑고 싶은가 | 칸마다 「예」. 2번은 보고서형 서류에서는 2번의 조건으로, 자소서에서는 「1. 자소서 문체」로 판정한 결과를 쓴다. 예: 그 칸에 탈락 사유가 되는 문장이 없고, 2·12·13번이 ✓이고, 읽은 뒤 남길 이유(직무와 닿는 결과)를 한 줄로 쓸 수 있다. 애매: 남길 이유는 있으나 2·12·13번 중 하나가 !다. 아니오: 탈락 사유 문장이 있거나 남길 이유를 쓸 수 없다. 「애매」·「아니오」면 이유가 된 문장을 적는다. 정의의 원본은 [panel/공통.md](panel/공통.md) 「판정 구분」이다 | |

## ⑧ 재심사와 마감: 고치며 생긴 흠이 없는가

| 항목 | ✓ 조건 | 본 대화 |
|---|---|---|
| 24 재판정 | 반영과 재작성으로 바뀐 칸마다 12~23번을 다시 판정했고(바뀌지 않은 칸은 다시 보지 않는다), 고친 문장은 원문과 뜻이 같다([writing-common.md](writing-common.md) 「고쳐 쓸 때 지킬 뜻」). 재판정 전의 판정은 그렇게 밝혔다 | ● |
| 25 글자 수 (본 대화 전용) | 글자 수를 스크립트 결과로 확인했고 제한 안에 든다([essay-kr.md](essay-kr.md) 「글자 수」) | ● |
