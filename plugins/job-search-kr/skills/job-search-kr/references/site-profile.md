# 구직 사이트 프로필 채우기

사람인·리멤버·캐치·자소설닷컴·원티드·잡코리아 같은 구직 사이트의 **본인 프로필·이력서**를 사용자가 요청할 때 채우고 저장한다. 지원서 제출은 여기에 들지 않는다. 링크드인은 [resume-en.md](resume-en.md) 「LinkedIn」을 따른다.

## 하는 것과 하지 않는 것

- 한다: 사용자가 직접 로그인해 둔 사이트에서(브라우저 도구, SKILL.md 「환경별 도구」), 사용자가 요청한 프로필 칸을 채우고 저장한다.
- 하지 않는다: 로그인, 입사 제안 수락, 로그인 쿠키·토큰·비밀번호 다루기, 여러 페이지를 자동으로 돌며 모으기.
- 약관·개인정보·민감정보 동의 칸은 체크하기 전에 사용자에게 묻는다. 한 번 허락받은 동의라도 사이트나 칸이 다르면 다시 묻는다.
- 지원서 제출은 이 문서가 아니라 [submit.md](submit.md)를 따른다.
- 사진·파일 업로드는 [submit.md](submit.md) 「파일 첨부」의 방식을 쓴다. 올린 뒤 서버에 저장된 값으로 확인한다.

## 순서

1. **지금 값을 읽는다.** 화면 글자보다 사이트가 불러오는 저장 데이터(개발자 도구 네트워크에 보이는 조회 응답)를 먼저 읽는다. 환경의 브라우저 도구가 페이지 스크립트를 실행하거나 네트워크 응답을 읽지 못하면, 사용자에게 확인 순서를 안내하거나 값을 붙여 달라고 요청한다. 빈 칸, 잘못 들어간 값, 다른 사이트와 어긋나는 값을 목록으로 만든다.
2. **프로필과 맞춘다.** 칸마다 `profile/profile.md` 의 사실이 있는지 본다. 없으면 채우지 않는다. 이력서 제목, 소개글 첫 문장, 희망 직무·지역·연봉은 프로필의 이직 대전제, 목표 직무군과 [strategy.md](strategy.md) 「지원 구분」을 따른다. 이력서를 여럿 만들 수 있는 사이트는 지원 구분별로 나눌 수 있다.
3. **빈 사실만 묻는다.** 한 번에 모아 선택지로 묻는다(연도, 넣을지 말지, 수준). 자유 서술로 한꺼번에 요청하지 않는다. 이미 프로필에 있는 것은 다시 묻지 않는다.
4. **글을 쓴다.** 먼저 목표 직무의 업계·직무·업무 분석 용어표를 읽는다. 없으면 [job-analysis.md](job-analysis.md)대로 만든다. 목표 업계가 지금과 다르면 [writing-common.md](writing-common.md) 「지원 업계의 말」을 따른다(본업 용어는 그 절의 자리별 규칙대로). 공통 규칙은 [writing-common.md](writing-common.md)를 따르고, 사이트 칸에만 있는 규칙은 아래 「글쓰기 기준」을 따른다.
5. **검토한다.** 소개글·경력기술서처럼 여러 문장인 글은 [review.md](review.md)의 인사 담당자 검토(`job-reviewer`, 사용자가 요청하면 네 역할 검토단)에게 맡긴다. 문서 종류는 「사이트 소개글」, 가상 인물은 목표 직무의 채용 담당자·헤드헌터로 준다. 반영 규칙은 [review.md](review.md)를 따른다.
6. **비교해 보이고 저장한다.** 칸마다 바꾸기 전과 후를 나란히 보인다. 저장은 사용자가 지시한 뒤에 한다.
7. **저장하고 서버 값으로 확인한다.** 저장 버튼 뒤 미리보기만 보고 끝내지 않는다. 다시 불러온 저장 데이터에 값이 들어갔는지 칸마다 확인한다.
8. **기록한다.** `profile/profile.md` 의 「구직 사이트 프로필 현황」에 날짜, 바꾼 칸, 대략으로 적은 값을 적는다. 남은 일은 그 절 맨 위에 한곳으로 모은다. 사용자가 새로 확인해 준 사실은 해당 절에도 적는다.

## 글쓰기 기준

- **소개글**: 첫 문장은 직함보다 무엇을 하는 사람인지. 문장은 첫머리 한두 문장까지만 쓰고, 그 아래 업무는 경력 설명과 같은 줄 형식으로 쓴다. 입사 후 문장과 첫 문장의 되풀이는 writing-common.md 「칸 용도」·「확정 문구와 문장 재사용」을 따른다. 목표와 먼 경력의 줄 수는 writing-common.md 「줄 수」를 따른다.
- **경력 설명·업무 묶음**: [writing-common.md](writing-common.md) 「경력 줄 기준」(업무 + 결과)을 따른다. 인사 담당자가 훑어보고 바로 알아보는 형태가 목표다.
  - 아래 줄 형식은 구직 사이트 칸(경력 설명, 소개, 사이트의 경력기술서 칸)에만 쓴다. 회사에 내는 경력기술서는 프로젝트 단위로 배경·한 일·결과를 쓰는 [resume-kr.md](resume-kr.md) 「경력기술서」 틀을 따른다.
  - 줄의 용어·결과·핵심 수단·묶음 단위·줄 수는 writing-common.md 「경력 줄 기준」·「줄 수」를 따른다.
  - 정규적으로 맡는 업무만 쓴다. 단기 지시 업무와 한 번 있었던 사례(설계 변경, 절차 수립 등)는 쓰지 않는다. 사례는 자기소개서 칸과 면접이 맡는다.
  - 묶음 제목은 `■ <업무 이름>` 한 줄이고(기간은 쓰지 않는다), 그 아래에 업무를 한 줄에 하나씩 `-`로 적는다.
  - 한 줄은 명사형으로 끝내고, 40자 안팎으로 쓴다. 기준이 필요하면 줄 앞에 둔다("사내 표준 양식 기준 …", "당사 회계정책 기준 …").
  - 괄호, 화살표, 상태 표시("개발 중", "운영 반영 전"), 다른 업무 줄에 붙는 수식어("생성형 AI 활용")를 쓰지 않는다. 직무 키워드가 아닌 도구 이름은 스킬 칸이 맡는다.
  - 이유·과정 설명은 자기소개서 칸과 면접이 맡는다.
  - 예외: 경력기술서 칸은 과제마다 제목 바로 아래에 `배경:` 한 줄을 둔다(어떤 프로젝트·시스템인지, 왜 시작했나).
  - 동사로 작성 주체를 드러낸다. 직접 만든 것은 "작성", 남이 만든 것을 본 것은 "검토", 정해서 넘긴 것은 "결정"·"지시". 누가 만들었는지를 따로 적지 않아도 동사로 구분되게 쓴다.

  - 저장한 뒤 다시 불러와 말머리 기호와 줄바꿈이 남았는지 확인한다. 사이트가 기호를 지우면 남는 기호로 바꿔 모든 칸을 같은 기호로 맞춘다.
- **이력서의 자기소개서 칸**: 소개글처럼 요약하지 않는다. [essay-kr.md](essay-kr.md)의 「구직 사이트 이력서의 자기소개서」를 따른다.
- **범위를 넓혀 쓰지 않는다**: [writing-common.md](writing-common.md) 「경력 줄 기준」의 「범위와 깊이」를 따른다.
- **대략인 값은 대략이라고 둔다**: 연도만 아는 활동 기간은 사이트가 월을 요구하면 넓게 적고, 사용자에게 월을 모른다고 알린다.
- **오해를 부르는 줄임말을 피한다**: 사용자가 「그 말은 다르게 읽힌다」고 하면 그 표현을 프로필에 적어 두고 모든 사이트에서 같이 고친다.

## 공개 범위

- 누구나 보는 공간(리멤버 커넥트 등)은 지금 회사 동료도 읽는다고 보고 쓴다.
  - 관심 분야·희망 직무처럼 이직을 드러내는 줄은 채용 서비스 전용 칸에만 둔다.
  - 동료가 함께 만든 일을 본인 공으로 읽히게 쓰지 않는다. 「전면 재구축」보다 「개선」처럼 낮춰 쓴다.
  - 회사 내부 문제는 writing-common.md 「서류에 쓰지 않는 것」대로 상태와 기능으로 쓴다.
- 재직 회사 열람 제한이 있는지 확인하고, 없으면 사용자에게 알린다.
- 제안 받기, 이력서 공개, 희망 조건은 사이트마다 지금 값을 읽어 보이고, 켤지는 사용자가 정한다. 링크드인은 [resume-en.md](resume-en.md) 「LinkedIn」을 따른다.

## 사이트 사이 일치

[writing-common.md](writing-common.md) 「사실 대조」의 서류 간 일치를 따른다. 고치지 못한 사이트는 기록에 남긴다.

## 사이트별 알려진 동작

사이트 화면과 칸 이름은 자주 바뀐다. 아래는 여러 사이트에서 흔히 겪는 동작이며, 작업할 때마다 실제 화면에서 다시 확인한다.

- 구직 상태나 경력 구분(신입·경력)을 바꾸면 이미 적은 경력 칸이 지워지는 사이트가 있다. 바꾸기 전에 사용자에게 알린다.
- 화면에 보이는 값만 바뀌고 저장되지 않는 칸이 있다. 저장한 뒤 편집 화면을 다시 열어 실제로 저장된 값을 확인한다.
- 저장 버튼을 누른 뒤 확인 창이나 광고 창이 저장을 가로막을 수 있다. 창을 닫은 뒤 저장이 끝났는지 확인한다. AI 문장을 이력서에 넣는 단추는 누르지 않는다.
- 일부 특수 문자(화살표 등)가 저장할 때 지워질 수 있다. 저장한 뒤 글을 다시 읽어 확인한다.
- 한 화면에 같은 내용을 쓰는 칸이 용도별(채용용, 네트워킹용 등)로 따로 있거나 탭을 바꿔야 나타나는 사이트가 있다. 어느 칸에 쓸지 사용자에게 확인한다.
- 칸을 채워도 완성도 숫자가 오르지 않을 수 있다. 숫자를 올리려고 사실이 아닌 내용을 넣지 않는다.
- 저장 전에 모든 칸의 글자 수 제한을 확인한다. 빈칸으로 보이는 화면에서 저장하면 기존 글이 지워질 수 있으므로, 기존 글이 불러와졌는지 먼저 본다.
- 확인 창 때문에 브라우저 도구가 진행하지 못하면 사용자에게 그 단계를 직접 하도록 안내한다.
