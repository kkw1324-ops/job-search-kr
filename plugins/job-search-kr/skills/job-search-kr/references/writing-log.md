# 작성기록 양식

자소서(지원서 문항, 회사 양식의 서술형 문항 포함)를 쓰는 지원 건마다 `applications/<회사>-<직무>/작성기록.md`를 이 양식으로 만든다. 이력서, 경력기술서, 영문 CV와 커버레터, 양식의 사실 칸, 구직 사이트 글, 대화에서 제안하는 문구에는 이 기록을 두지 않고, 메인이 읽은 파일과 확인한 사실을 보고에 적는다. 필수 과정(SKILL.md 「서류 문구의 필수 과정」) ①을 시작할 때 메인이 만든다. 저장 훅과 사후 감사 스크립트(`write_audit.py`)가 이 파일을 읽으므로 표의 머리글, 단계 이름, 절 이름을 바꾸지 않는다. 저장 훅은 자소서 본문 파일(.md, .docx, .txt, .hwp, .hwpx)만 막고, 검토 결과, 예상 질문, 글자 수 확인, 메모, 백업 파일은 막지 않는다.

## 칸을 채우는 규칙

- **산출물**: 그 단계에서 남긴 파일 이름이나 결과 한 줄. 파일이면 지원 폴더 안의 이름을 쓰고(예: `배정표.md`), 지원 폴더 밖의 파일은 `work/직무분석/<직무>.md`처럼 작업 폴더에서 시작하는 경로로 쓴다.
- **찾아본 곳**: 읽은 파일과 절. 「없음」으로 적기 전에 찾아본 곳을 모두 적는다.
- **질문과 답**: 사용자에게 물은 것과 답한 그대로의 말. 없으면 비운다.
- **생략 승인**: 사용자가 그 단계의 생략과 이유를 듣고 답한 날짜와 말. 생략하지 않았으면 비운다. 사실을 지키는 단계(③의 사실 확인, ⑦의 프로필 대조)와 글자 수 확인은 생략을 제안하지 않는다(SKILL.md 「생략과 시간 부족」).
- **작성**: `<담당>, <YYYY-MM-DD>` 형식. 담당은 메인, job-writer, 검토 역할 이름 가운데 하나다. ⑥과 ⑧처럼 담당이 여럿인 단계는 메인이 적고, 그 단계에서 실제로 일한 역할의 이름을 모두 적는다(예: `서류·국어·job-writer, <YYYY-MM-DD>`).
- **확인**: `<누가>, <YYYY-MM-DD>, <열어 본 파일>` 형식. 그 단계의 작성자가 아닌 쪽이 실제 산출물을 열어 본 뒤에 적는다. 작성자는 자기 단계의 확인 칸을 채우지 않는다.
  - ①~③(메인이 작성): `job-writer`가 ④를 시작하면서 세 줄의 기록과 거기 적힌 파일을 열어 보고 받아들일 때 적는다. 기록이 비어 있으면 `job-writer`는 시작하지 않고 빠진 것을 돌려준다.
  - ④, ⑤(`job-writer`가 작성): 메인이 `배정표.md`와 초안을 열어 본 뒤에 적는다.
  - ⑥~⑧: 심사 역할(job-reviewer)은 읽기만 하고 기록을 쓰지 못하므로, 메인이 그 결과를 `검토.md`에서 열어 본 뒤에 적는다. 심사와 판정은 역할이, 기록과 확인은 메인이 한다.
- `-`나 `.`만 적은 칸은 빈칸으로 본다.
- 칸 안에 `|`와 줄바꿈을 쓰지 않는다. 길면 지원 폴더의 파일에 쓰고 이름만 적는다.

## 양식

```markdown
# 작성기록: <회사>-<직무>

대상 문항: <문항 원문 파일 또는 출처>

| 단계 | 산출물 | 찾아본 곳 | 질문과 답 | 생략 승인 | 작성 | 확인 |
|---|---|---|---|---|---|---|
| ① 지원 가능 확인 |  |  |  |  |  |  |
| ② 회사·직무 재료 확인 |  |  |  |  |  |  |
| ③ 경험 재료 확인 |  |  |  |  |  |  |
| ④ 칸 설계 |  |  |  |  |  |  |
| ⑤ 작성 |  |  |  |  |  |  |
| ⑥ 작문 심사와 칸 재작성 |  |  |  |  |  |  |
| ⑦ 사실·합격 심사 |  |  |  |  |  |  |
| ⑧ 재심사와 마감 |  |  |  |  |  |  |
| ⑨ 사용자 보고 |  |  |  |  |  |  |
| ⑩ 제출 준비 |  |  |  |  |  |  |

## 사용자 통과

<!-- 사용자가 기록 없이 저장하라고 지시한 경우만 한 줄씩: - YYYY-MM-DD <파일 이름>: 「사용자의 말」 -->
```

## 사용자 통과를 적을 때

사용자가 기록 없이 저장하라고 분명히 지시했을 때만 「사용자 통과」 절에 `- YYYY-MM-DD <파일 이름>: 「사용자의 말」` 한 줄을 더하고 저장한다. 이 줄이 있으면 저장 훅은 그 파일의 기록 확인과 작성 주체 제한을 건너뛴다. 사용자의 말 없이 이 줄을 쓰지 않는다.

## 사후 감사

⑨ 사용자 보고 전에 메인이 실행한다. `work/감사대상.txt`의 첫 줄에 지원 폴더 경로(예: `applications/<회사>-<직무>`)를 쓰고, 작업 폴더에서 `python3 <스킬 폴더>/scripts/write_audit.py run`을 실행한다. 결과 단계 완료표는 화면과 `work/감사결과.md`에 나오며, 문제가 없으면 끝 코드 0, 있으면 1, 감사 대상이 없으면 2다. 보고 첫머리에 이 표를 그대로 둔다. 감사가 보는 것은 단계마다 산출물과 확인이 있는지, 산출물 파일이 실제로 있는지, ④~⑧의 작성 날짜 순서, 작성자가 자기 단계를 확인했는지다.
