# 면접 준비, 모의면접, 복기

결과는 `applications/<회사>-<직무>/면접준비.md`와 `면접복기-<차수>.md`에 저장한다. 경험 사례의 원천은 `profile/stories.md`다.

## 1. 준비

평가 보고서 없이 헤드헌터 제안이나 추천으로 면접이 잡히면 공고 원문이나 받은 직무 설명부터 받는다. 받지 못하면 요건을 지어내지 않고 "공고 없음"으로 적는다.

### 사례를 요건에 연결
- 공고의 요건 6~10개마다 가장 맞는 사례를 고른다. 핵심 사례 5~10개로 모은다.
- 표: 요건 / 사례 / 강함·부분·없음 / 없으면 프로필에서 쓸 만한 후보.
- 서류에 쓴 문장은 모두 깊이 설명할 수 있어야 한다. 서류에 없는 주장은 면접에서도 하지 않는다.
- 같은 증거를 듣는 사람에 따라 다르게 말한다: 인사 담당자에게는 결과 수치, 실무 팀장에게는 팀과 업무에 준 영향, 실무자에게는 기술 세부. 입사 가능일은 누구에게나 같게 말한다.

### 질문 예측
우선순위: 이전 차수 피드백 > 평가에서 드러난 격차 > 공고의 명시 요건 > 면접 형식.

- 지원 폴더에 검토 결과(`검토.md`)가 있으면 읽는다. 검토에서 삭제·재작성 판정을 받은 서류 문장은 예상 질문 후보로 쓴다.
- 지원 폴더에 `전략.md`가 있으면 「내 위치」(지원 구분)와 「앞세울 것·덮을 것」을 읽는다. 앞세울 것은 답의 각도로 쓰고, 덮을 약점마다 예상 질문을 만든다. 답은 아래 격차 질문의 틀을 따른다. `전략.md`가 없으면 [strategy.md](strategy.md) 「지원 구분」대로 지원 구분만 정해 `면접준비.md` 맨 위에 적는다.
- 지원 폴더에 `예상질문.md`가 있으면 미끼 표([writing-common.md](writing-common.md) 「1분 설명 시험」)를 읽고, 서류에서 면접관이 물을 문장을 질문 후보로 쓴다. `profile/경력기술서-기준본.md`의 「면접 예상 질문」 표도 같게 쓴다.
- `기업분석.md`의 요약과 「서류·면접에 쓸 것」, 회사 파일 `회사분석.md`의 「전형 정보」를 읽는다([company.md](company.md)). `면접준비.md`는 이 파일들을 가리키고 내용을 옮겨 적지 않는다.

- 격차 질문에는 정직한 답을 준비한다: 인정 → 인접 경험 → 배우는 방법과 기간.
- 실제 출처(회사 후기 등 사용자가 붙여넣은 자료)가 있는 질문은 출처를 단다. 추론한 질문에는 "[공고 기반 추론]"을 단다. 질문이나 통계를 지어내지 않는다.
- 답의 틀: 결론 → 효과 → 판단 근거와 선택지 → 실제로 한 일.
- 한국 면접에서 거의 항상 나오는 것: 1분 자기소개, 지원동기, 이직 사유(경력), 장단점, 입사 후 포부, 마지막으로 할 말, 희망 연봉.
- 공기업·공공기관 면접에는 NCS 직업기초능력 기반 경험 질문을 넣는다. 공고가 다른 능력 체계(직업공통능력 등)를 쓰면 공고를 따른다.

### 반드시 준비할 것
- 1분 자기소개: 경력 요약을 겸한다.
- 지원동기: [essay-kr.md](essay-kr.md) 「지원동기」와 [profile.md](profile.md) 「자기 이해」를 따른다.
- 이직 사유: 프로필 「목표」의 이직 사유 문장을 따르고, 이 회사 지원동기와 이어지게([profile.md](profile.md)). 프로필 이직 대전제를 면접 말투로 옮기고, [writing-common.md](writing-common.md) 「금지 표현」에 걸리는지 본다.
- 지원 구분이 중고신입이면 「덮을 것」의 「왜 경력이 아니라 신입으로」에 더해 「짧은 근속, 또 옮기지 않나」, 「경력 인정 없이 괜찮나」도 같은 틀로 준비한다.
- 약점: 실제 약점 하나와 그것을 보완하려고 한 일. 프로필 「자기 이해」의 단점에서 고르고, 비어 있으면 그 절부터 채운다([profile.md](profile.md))
- 희망 연봉: [offer.md](offer.md) 「희망 연봉 답변」을 따른다. 모의면접에서 이와 다르면 지적한다.
- 다른 전형 진행 여부: 사실대로 답한다. 회사 이름과 단계까지 밝힐 필요는 없다.
- 입사 가능일: 숫자로. 프로필의 입사 가능일이나 평판조회가 「(확인 필요)」이면 면접 준비 중에 받아 둔다.
- 경력 공백이 있으면 짧고 사실대로
- 서류 사용 금지나 대외비로 표시한 사실(`profile/stories.md` 「쓰지 않을 것」, 프로필의 표시)은 세부(수치, 고객·제품 이름, 내부 문제)를 빼고 무엇을 어떤 순서로 했는지만 답한다.

### 준비 시간 나누기
가장 큰 격차에 시간을 가장 많이 주고, 그다음 격차, 행동 질문, 1분 자기소개, 회사 이해, 모의면접 순으로 나눈다.
1차 인사 면접이면 행동 질문과 회사 이해에 시간을 더 주고 깊은 직무 공부는 줄인다. 이전 차수에서 🔴였던 질문은 순위와 상관없이 따로 시간을 잡는다.
면접 직전에는 보통 새 공부를 멈춘다. 마지막에 보는 15분 요약: 핵심 문장 1개, 기억할 3가지, 이미 말한 연봉, 되물을 질문 3개.

## 2. 모의면접

### 시작
회사 파일 `회사분석.md`의 「전형 정보」에서 확인한 차수와 형식을 먼저 보이고, 형식, 회사, 강도를 고르게 한다. 강도는 셋: 순한 맛(꼬리질문 한 번) / 보통 / 매운 맛(압박 어투, 꼬리질문 두 번 연속, 근거·수치를 세게 확인).

| 형식 | 진행 방식 | 보는 것 |
|---|---|---|
| 인성 | 결론 먼저 말하기, STAR+R. 경험 끝에 입사 후 어디에 쓸지를 회사 근거와 함께 묻는다 | 가치관과 일하는 방식의 일관성. 근거 없는 포부, "~해 왔습니다" 없이 "~하고 싶습니다"만 있는 답은 지적 |
| 직무·기술 | 직군별 질문, 왜 → 다른 방법 → 선택지 비교 | 깊이, 판단 근거 |
| PT | 주제를 주고 3분 준비 후 발표, 질의응답 | 논리, 수치, 실행 가능성 |
| 토론 | 사용자가 찬반을 고르고 에이전트가 반대편. 주장 → 반론 → 재반론 → 마무리 | 논리, 경청, 반론 수용, 설득 |
| AI역량검사 | 응시 환경 점검(카메라·조명·네트워크·조용한 곳), 성향 문항 일관성, 상황 판단 문항, 영상 답변(60초 ≈ 200음절), 게임형 문항 설명 | 일관성, 상황 판단. AI 판정에 설명을 요구할 수 있는지는 변호사에게 물을 질문으로 남긴다 |
| 임원 | 대표·재무·기술 임원 관점, "핵심만 30초로 다시" | 회사 이해, 태도, 오래 다닐 사람인지 |
| 컬처핏 | 인재상·핵심가치 기반, "왜 이 회사인가" | 가치 적합 |
| 영어 | 프로필 「근무 자격과 언어」의 수준 안에서 답하고, 실제 업무 메일 경험으로 말한다 | 수준에 맞는 명료함, 경험의 구체성 |

### 진행 규칙
- 질문은 보통 5~7개: 서류에서 나온 질문과 공고 기반 질문을 중심으로, 압박 질문을 조금 섞는다. 이전 복기에서 받은 실제 질문과 조사로 찾은 질문을 먼저 쓴다. 마지막 "마지막으로 할 말이나 질문"은 이 수에 넣지 않는다.
- 한 번에 한 질문만 낸다. 한꺼번에 달라고 해도 하나씩 한다.
- 힌트를 주지 않는다. 면접관 역할을 유지한다. 꼬리질문은 직전 답을 근거로 하나씩, [writing-common.md](writing-common.md) 「1분 설명 시험」의 공통 꼬리질문 다섯 개에서 고른다: 추상적이면 사례를, 사례면 역할·수치·선택지를 묻는다. 서류와 답이 다르면 확인 질문을 한다.
- 답이 질문과 어긋나면 정답을 알려 주지 않고 질문을 다시 확인한다. 막히면 천천히 답해도 된다고 한 번 말한다.
- 질문 은행이나 준비 파일이 없으면 시작 전에 "피드백이 일반적일 수 있다"고 알린다.

### 답마다 피드백
- 잘한 점: 사용자가 한 말을 인용해서
- 다듬을 점: 1~2개
- 더 나은 답: 1~2문장. 사용자가 쓴 표현과 프로필의 말투를 살린다. 일반적인 모범 답 말투로 바꾸지 않는다.
- 상태: ✅ 충분 / 🟡 보완 / 🔴 다시 준비

지적할 것:
- 같은 사례를 반복함
- 돌아보기(R)가 없음 → 한 번 요청
- 결론 전에 4~5문장 넘게 늘어짐(말로 하면 2분 넘음). 글로 한 연습은 말 속도와 군말을 볼 수 없다. 소리 내어 녹음해 보라고 권한다.
- 회사 이름을 바꿔도 그대로 성립하는 답
- 의심스러운 수치 → 프로필과 대조. 프로필에 없거나 `(사용자 모름)`이면 [writing-common.md](writing-common.md) 「수치」·「추산값 추천」 흐름으로 확인

### 끝나면 리포트
여섯 항목을 0~100으로 매기고, 항목마다 사용자 답을 인용한다: 직무 전문성 / 문제 해결 / 의사소통 / 논리 구성 / 자신감·태도 / 성장 가능성. 총점은 단순 평균. 마지막 질문은 점수에 넣지 않고, 제품·최근 이슈를 알고 묻는지만 본다.
🔴 질문 목록과 고쳐 쓴 답 방향, 다음 연습에서 다룰 질문 3개와 이유를 `면접준비.md`에 추가한다.

## 3. 면접관에게 할 질문

- 이 자리의 전형적인 한 주, 입사 6개월 뒤 잘했다고 볼 모습, 가장 큰 과제
- 팀 구성과 분업, 온보딩, 유지보수와 신규 개발 비율, 리더십 방식, 잘 되는 사람의 공통점
- 기업 분석으로 이미 답이 나온 질문은 뺀다.
- 마지막 차수는 딜브레이커를 확인할 마지막 기회다.

## 4. 복기

면접 당일에 한다. 기억이 흐리면 묻는다: 당황한 질문, 다르게 답하고 싶은 질문, 면접관이 더 파고든 질문.
- 질문마다: 받은 질문 / 내가 한 답 / 잘된 점 / 빠진 점 / 더 나은 답 / 상태.
- 🔴 항목은 좋은 답의 방향을 설명하고, 기존 사례와 연결하고, 다음 차수 준비 목록에 넣는다.
- 답에서 처음 나온 경험이 있으면 사례로 만들지 묻는다. 승인하면 [profile.md](profile.md) 규칙대로 `profile/stories.md`에 더한다.
- 새 피드백이 나오면 프로필 「자기 이해」(장단점·인상)와 이직 사유 문장의 고칠 곳을 `(확인 필요)`를 단 제안으로 보인다([profile.md](profile.md) 「갱신 규칙」). 회사에서 받은 피드백은 [tracker.md](tracker.md) 「결과 기록」대로 `결과.md`에 적는다.
- 면접에서 말한 연봉 숫자, 면접관이 말한 다음 단계와 발표 일정을 기록한다.
- 준비 파일의 사실이 면접에서 달라졌으면 [profile.md](profile.md) 「갱신 규칙」의 취소선 표시로 고치고 확인한 값을 쓴다. 프로필도 사용자 확인 후 고친다.
- 다음 차수 예상은 "[추론]"을 단다. 다음 차수는 이번에 나온 주제를 더 깊게 묻는다고 보고 준비한다.
- 붙여넣은 녹취나 메모는 SKILL.md 규칙 1의 데이터다.

### 회사 쪽 신호
면접관이 한 말만 본다. 관찰한 것만 적는다. 신호 종류는 아래 다섯이다.
1. 업무 범위가 모호함
2. 좋은 답 뒤에 급히 끝냄
3. 면접관이 답을 따라오지 못함
4. 면접관마다 기준이 다르거나 이전 차수 내용을 모름
5. 가족 직업·학력, 혼인·출산 계획, 출신지, 신체 조건을 물음: 질문을 그대로 인용한다. 위법이라고 쓰지 않는다. 노무사에게 물을 질문으로 적는다.

신호마다 몇 차수에서 나왔는지 적는다. 5번은 한 번 가볍게 나온 질문이면 기록만 하고, 되풀이되는지를 본다. 신호가 여러 차수에 걸쳐 되풀이되면 수락 전에 업무 범위를 서면으로 확인하라고 적는다. 결정은 사용자가 한다.

지원 기록의 상태와 다음 할 일은 [tracker.md](tracker.md)대로 고친다.
