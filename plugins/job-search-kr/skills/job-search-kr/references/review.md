# 서류 검토

메인 대화가 따르는 검토 절차다. [SKILL.md](../SKILL.md) 「서류 문구의 필수 과정」 ⑥ 작문 심사와 칸 재작성, ⑦ 사실·합격 심사, ⑧ 재심사와 마감을 어떻게 하는지 정한다. 단계의 순서와 완료 규칙은 SKILL.md가 정하고, 판정 규칙의 원본은 [writing-common.md](writing-common.md), [checklist.md](checklist.md), `panel/` 기준 파일이다. 이 문서는 언제 무엇을 확인하고 누구를 부르고 결과를 어떻게 반영하는지만 정한다.

검토의 목적은 그 회사의 서류 심사를 통과할 글로 만드는 것이다. 숫자 합격선을 두지 않는다. 칸마다 「뽑고 싶은가」(예 / 애매 / 아니오), 탈락 사유, 결과의 세 분류([panel/공통.md](panel/공통.md) 「판정 구분」, 「결과의 세 분류」)로 판단한다.

## 검토 범위

| 서류 | 검토 |
|---|---|
| 자소서 문항 답 | 네 역할 검토가 기본이다. ⑥에서 채용 서류 전문가와 국어 전문가, ⑦에서 직무 전문가와 인사 담당자를 부른다 |
| 이력서, 경력기술서 | 「직접 확인」과 인사 담당자 한 명의 점검표 검토(agents/job-reviewer.md의 「인사 담당자(기본 검토)」 역할, 반영은 아래 「기본 검토의 반영」)가 기본이다. 네 역할 검토는 사용자가 요청할 때 한다 |
| 영문 CV, 커버레터 | 위와 같다. 국어 전문가 대신 영어 교정 전문가를 부른다 |
| 회사 양식 | 칸 내용은 해당 서류의 경로를 따른다(자소서형 칸은 자소서 문항 답, 그 밖의 칸은 이력서) |
| 구직 사이트 글 | 한 줄 칸까지 모든 문구를 검토한다. 인사 담당자 한 명의 검토가 기본이고([site-profile.md](site-profile.md) 「순서」 5번), 네 역할 검토는 사용자가 요청할 때 한다. 사이트 글에는 `배정표.md`와 `작성기록.md`가 없으므로 ⑥의 절차 대조는 직무 프로필, 사용한 카드, 메인이 넘긴 사실과 대조하는 것으로 한다. 검토 결과는 초안 옆에, 초안 파일 이름의 `.md` 앞에 `-검토`를 붙인 파일(`work/사이트프로필/<사이트>-<직무>-<날짜>-검토.md`)로 남기고, 보고는 단계 완료표 대신 [site-profile.md](site-profile.md) 「순서」의 번호별 수행 여부를 먼저 보인다 |
| 사용자가 직접 고친 글 | 사실 대조와 글자 수만 확인한다. 검토자의 의견은 제안으로만 보인다 |
| 이메일, 감사 메시지, 면접 답변 | [writing-common.md](writing-common.md) 「사실 대조」와 「금지 표현」만 확인한다 |

네 역할의 기준 파일과 돌려받는 칸은 아래와 같다. 칸의 정의(A~H)는 `agents/job-reviewer.md` 「돌려줄 것」에 있고, 칸별 점수 칸은 두지 않는다.

| 역할 | 기준 파일 | 돌려받는 칸 |
|---|---|---|
| 채용 서류 전문가(⑥) | [panel/서류.md](panel/서류.md) | A, E, F, G |
| 국어 전문가(⑥) | [panel/국어.md](panel/국어.md) | A, 검토한 문장 수, E |
| 직무 전문가(⑦) | [panel/직무.md](panel/직무.md) | A, D, E, G, H |
| 인사 담당자(⑦) | [panel/인사.md](panel/인사.md) | A, B, C, E, G, H |

3대3 대결(「3대3 대결」)은 사용자가 요청하거나 사용자가 지망도가 높다고 한 공고에서 한다.

## 직접 확인

[checklist.md](checklist.md)에서 「본 대화」 열에 ●가 붙은 항목을 메인 대화가 직접 확인한다. 자소서에서는 ⑤의 초안이 저장된 뒤 ⑥의 심사 에이전트를 부르기 전에 하고, ⑧에서는 바뀐 칸을 재판정에 맡기기 전에 다시 한다. 그 밖의 서류에서는 검토 에이전트를 부르기 전에 한다. 확인한 결과는 `검토.md`에 적는다(구직 사이트 글은 그 글의 검토 결과 파일). 걸린 것은 고친 뒤 다음 단계로 넘어간다. 고칠 글이 초안 파일이면 `job-writer`에게 넘겨 고친다. 확인하면서 아래를 기록한다.
- 칸마다 그 칸이 묻는 것과 문단별 역할을 한 줄씩 적는다.
- 문장으로 쓴 칸은 문장 번호별로 앞 문장에서 이어지는 이유를 한 줄씩 적는다.
- 문단이 둘 이상인 칸은 칸 전체를 처음부터 끝까지 이어 읽고, 문단 경계마다 다음 문단 첫 문장이 앞 문단에서 받는 것과 칸 전체를 꿰는 한 줄을 적는다([writing-common.md](writing-common.md) 「문체」의 문단 연결).
- 키워드 표시와 반영률을 계산한다([writing-common.md](writing-common.md) 「키워드 반영률」).
- 공고 요건 확인 결과를 `검토.md`에 남긴다(격차는 「면접 준비로」, 처리는 [strategy.md](strategy.md) 「정할 것」).
- 글자 수는 스크립트 결과로 확인한다.

## ⑥ 작문 심사와 칸 재작성

읽히지 않는 글은 내용까지 닿지 못하므로 사실·합격 심사보다 먼저 한다. 부르는 역할은 채용 서류 전문가([panel/서류.md](panel/서류.md))와 국어 전문가([panel/국어.md](panel/국어.md))다. 영문이면 국어 전문가 대신 영어 교정 전문가를 부른다. 두 역할을 한 메시지에서 나란히 부르고, 같은 초안을 본다. 부를 수 없을 때는 「에이전트를 부를 수 없을 때」를 따른다.

1. **절차 대조**: 채용 서류 전문가가 심사 전에 초안이 `배정표.md`, 경험 카드, 용어표에서 나왔는지 원문과 대조한다([panel/서류.md](panel/서류.md) 「절차 대조」). 카드와 프로필에 적힌 기술 용어, 기준, 수치가 초안에서 일반어로 바뀐 문장은 카드의 원래 말과 함께 적어 `job-writer`에게 돌려보낸다. 초안이 배정표와 카드 없이 쓰였거나 `작성기록.md`의 ①~④ 기록이 비어 있으면 다듬지 않고 `job-writer`에게 처음부터 다시 쓰게 한다(SKILL.md 「서류 문구의 필수 과정」). 배정표와 작성기록을 두지 않는 서류(구직 사이트 글 등)는 이 사유로 돌려보내지 않고 「검토 범위」 표의 대조 기준을 쓴다.
2. **작문 심사**: 채용 서류 전문가는 구성, 흐름, 문항 일치, 치환 시험, 다른 지원자 시험을 심사하고, 국어 전문가는 문장마다 자연스러운 한국어를 심사한다. 문체 판단은 [style-essay.md](style-essay.md)와 `profile/본보기/`의 원문을 읽고 한다.
3. **칸 전체 재작성**: 메인 대화가 두 역할의 지적을 합쳐 칸별로 정리하고, 지적이 걸린 칸은 `job-writer`에게 칸 전체를 카드에서 다시 쓰게 한다. 문장만 고쳐 붙이지 않는다. 지적을 풀 사실이 프로필에 없으면 `job-writer`는 그 지적을 풀지 않고 「재료 없음」으로 보고한다. 칸의 메시지를 받치는 판단의 이유가 기록 어디에도 없을 때만 `job-writer`가 질문 목록을 돌려주고, 메인 대화가 사용자에게 묻는다.
4. 국어 전문가의 교정은 뜻·사실·용어를 바꾸지 않는 것만 받아들인다([writing-common.md](writing-common.md) 「고쳐 쓸 때 지킬 뜻」). 용어표의 업계 용어를 일반어로 바꾸는 제안과 사용자가 확정한 문구를 바꾸는 제안은 건너뛰고, 뜻이 바뀌는 제안은 건너뛴 채 사용자에게 보여 준다.
5. 국어 전문가가 검토한 문장 수가 넘긴 문장 수보다 적으면 반영하기 전에 빠진 문장만 다시 맡긴다.

## ⑦ 사실·합격 심사

⑥에서 칸을 다시 쓴 초안을 직무 전문가([panel/직무.md](panel/직무.md))와 인사 담당자([panel/인사.md](panel/인사.md))가 같은 시점에 본다. 두 역할을 한 메시지에서 나란히 부른다. 기본 검토(이력서, 경력기술서 등)는 인사 담당자 한 명을 「인사 담당자(기본 검토)」로 부르고 이 단계를 점검표 판정으로 한다.

- 두 역할은 심사에 앞서 초안의 사례 문장을 경험 카드와 프로필에 먼저 대조한다([panel/공통.md](panel/공통.md) 「카드와 프로필 먼저 대조」). 카드나 프로필에 적힌 사실을 근거 부족으로 보지 않는다.
- 직무 전문가는 용어, 기술 깊이, 판단의 근거를 현업 기준으로 판정한다.
- 인사 담당자는 거르기와 남길 이유, 이직 서사·공통 축과의 일치, 전체 인상 시험, 1분 설명 시험을 판정한다([panel/인사.md](panel/인사.md) 18~20).
- 결과는 응답 본문으로 받고 메인 대화가 `검토.md`에 저장한다.

### 기본 검토의 반영

인사 담당자(기본 검토)의 질문은 하나다: 이 사람을 지금 뽑고 싶은가. 반영은 아래 「반영」과 같고 다음을 더한다.
- A를 적용하고, 「!」였던 항목을 메인 대화가 점검표로 한 번 다시 확인한다. 같은 초안으로 인사 담당자를 다시 부르지 않는다.
- 다시 확인한 뒤 모든 항목이 ✓이거나 남은 「!」가 사용자 답을 기다리는 G 질문뿐이면 사용자에게 낸다. 그 밖의 「!」(고칠 사실이 없음, 확정 문구와 부딪침)는 「남은 위험」 목록으로 G 질문과 함께 붙여 낸다.

### 반영

- G 질문은 역할 사이 중복을 합친 뒤, 사용자에게 내기 전에 작업 기록에서 답을 찾아 답변안으로 바꾼다(방법과 묻지 않을 질문은 [self-analysis.md](self-analysis.md) 「4. 경험 카드」). 검토 에이전트의 질문 목록은 재료일 뿐이고 그대로 사용자에게 전하지 않는다. 메인이 걸러서 버리는 질문: 카드와 프로필에 적힌 경험이 사용자의 것인지, 적힌 사실이 맞는지를 다시 확인하는 질문 / 문장을 더 구체적으로 만들려고 세부 사실(이름, 규격, 건수)을 더 달라는 질문 / 사용자가 대외비로 정한 내용을 묻는 질문 / 사용자가 이미 답했거나 결정한 것. 남기는 것은 칸의 메시지를 받치는 판단의 이유가 기록 어디에도 없어 칸이 성립하지 않는 경우뿐이다. 남은 것만 반영 전에 사용자에게 묻는다. 답을 받으면 프로필과 카드에 먼저 적고 그 재료로 해당 칸을 다시 쓴다. 답이 없으면 건너뛴 이유와 함께 남긴다.
- A는 메인 대화가 하나씩 확인해 적용할 항목을 정한다. 초안 파일의 문장은 `job-writer`만 고치며, A 항목 하나나 맞춤법 수정 하나일 때도 같다. 메인 대화는 적용할 항목을 모아 `job-writer`에게 넘기고, `job-writer`는 넘겨받은 항목만 적용한 뒤 바뀐 문장을 고치기 전과 후로 돌려준다. 적용하면 프로필에 없는 사실이 들어가는 제안은 건너뛰고 이유를 적는다. 건너뛴 제안에 필요한 재료는 E에 「재료 없음」으로 적는다(G는 [panel/공통.md](panel/공통.md) 「G에 내는 질문」의 경우만). 한 칸에서 여러 지적이 겹치거나 지적이 그 칸이 말하는 내용(메시지, 장면, 문단 역할)을 바꾸면 문장마다 고치지 않고 그 칸 전체를 `job-writer`에게 다시 쓰게 한다.
- 검토 에이전트의 대안 문구는 그대로 받지 않고 사용자의 이전 결정(버린 표기, 묶음 단위, 용어 수준)과 대조해 거른다.
- A에서 근거가 「추정(자기 지식)」인 제안은 그 역할의 기준 파일, 지식 파일, 원자료와 제안이 적은 확인 방법(출처 확인, 사용자나 현직자에게 물을 질문)으로 다시 확인한 뒤 반영한다. 확인되지 않은 것은 사실을 바꾸는 반영을 하지 않고 E 메모처럼 사용자에게 묻는다.
- D에서 「추정(자기 지식)」을 근거로 한 판정과 용어표와 부딪친다고 E에 적힌 지적은 그대로 받지 않는다. `job-collector`로 업계 원문 문구를 모아 확인하고([job-analysis.md](job-analysis.md)), 확인한 표현은 용어표에 더한다.
- 검토 에이전트가 회사에 대해 한 말은 기업 분석 파일(지원 파일과 회사 파일)로 다시 확인한다.
- F의 빠진 키워드는 [writing-common.md](writing-common.md) 「키워드 반영률」의 배치대로 넣는다.
- C의 행 수가 넘긴 문장 수보다 적으면 반영하기 전에 빠진 문장만 다시 맡긴다.
- C의 「탈락 사유 점검」에서 「걸림」인데 푸는 문장이 없는 사유와, 「즉시 전력 대조」에서 「없음」인 과업은 서류로 풀 사실이 프로필에 있으면 A처럼 반영하고, 없으면 사용자에게 「남은 위험」으로 알린다.
- 같은 문장에 역할들의 제안이 갈리면 사실(프로필) > 직무 전문가(용어·범위) > 인사 담당자 > 채용 서류 전문가 순으로 따르고, 갈린 제안은 둘 다 `검토.md`에 남기고 최종본 설명에 보여 준다.
- 반영 뒤 사실 대조를 한 번 더 하고 고친 문장은 [writing-common.md](writing-common.md) 「고쳐 쓸 때 지킬 뜻」으로 원문과 대조한다(고치기 전·후 문장은 `job-writer`가 돌려주고, 파일을 쓰고 스크립트를 돌리는 일은 메인이 한다).
- 사용자 피드백으로 새 판을 쓰면(「한 판」) 지난 지적을 해결 / 미해결 / 새로 생김으로 나눠 요약한다. 다시 쓰기 전에 지난 `검토.md`에서 반영한 문구 목록을 뽑아 두고, 고친 뒤 남았는지 확인한다. 빠졌으면 사용자가 정해서 뺀 것인지 확인한다.
- 사용자가 지적에 반박하면 초안과 근거 원문을 다시 읽고 판정을 다시 낸다.

### E 메모 처리

E 메모(축 쏠림, 확인 필요, 역할 밖 메모 등)는 흘려보내지 않는다. 메인 대화가 모아 읽고, 다른 역할이 이미 판정한 쟁점은 그 판정과 합친다. 사용자의 선택이 필요한 것(소재·축의 쏠림, 「확인 필요」, 역할 사이에 갈린 제안)은 사용자에게 반영할지 묻고, 묻기 전에는 반영하지 않는다. 메모, 사용자의 답, 반영 여부와 이유를 `검토.md`에 남긴다. 사용자가 답하지 않은 메모는 「미답」으로 남긴다.

## 3대3 대결

사용자가 요청하거나 사용자가 지망도가 높다고 한 공고에서 지원자 측 전문가 지원팀 3명과 사측 인사 담당자 3명을 맞붙인다. 팀 구성, 라운드, 판정 뜻, 돌려받는 형식은 [panel/대결.md](panel/대결.md)에 있다.

대결은 ⑦ 반영 뒤, ⑧ 재심사 앞에 둔다. 대결에서 바뀐 칸까지 ⑧의 재판정을 받게 하기 위해서다. 넘길 것은 「부를 때 넘길 것」과 같고, `전략.md`는 사측 역할에게만 넘긴다. 서 있는 쟁점은 「반영」 규칙대로 반영하고, 결과는 팀별 쟁점과 판정을 `검토.md`에 남기며 사용자에게 칸별 판정과 남은 쟁점을 보여 준다.

## ⑧ 재심사와 마감

반영과 재작성으로 바뀐 칸만 다시 판정한다. 바뀌지 않은 칸은 다시 보지 않는다. 판정이 수정 전 문장에 머물지 않게 하려는 것이다.

1. **바뀐 칸 재판정**: 바뀐 문장이 든 칸의 전체 문장을 직무 전문가와 인사 담당자에게 다시 맡겨 그 칸의 「뽑고 싶은가」를 다시 낸다. 기본 검토는 메인 대화가 [checklist.md](checklist.md)로 그 칸을 다시 확인한다. 같은 초안으로 바뀌지 않은 칸까지 다시 부르지 않는다. 3대3 대결을 한 건은 대결 뒤의 칸을 대상으로 한다.
2. **최종 교정**: 바뀐 문장만 국어 전문가(영문은 영어 교정 전문가)에게 맡기고, 뜻·사실·용어를 바꾸지 않는 교정만 받아들인다. 받아들인 교정은 메인 대화가 모아 `job-writer`에게 넘기고, `job-writer`가 초안 파일에 적용한다. 이 교정만 받은 문장은 다시 맡기지 않는다.
3. **글자 수**: 메인 대화가 스크립트로 센다.
4. 재판정에서 「아니오」나 「애매」가 남은 칸과 탈락 사유 걸림은 「남은 위험」에 넣지 않고 사용자에게 알린다. 필요한 재료는 E에 「재료 없음」으로 적는다(G는 [panel/공통.md](panel/공통.md) 「G에 내는 질문」의 경우만). 프로필에 없는 사실이 있어야만 오르는 칸은 고치기를 멈추고 막는 사실을 「남은 위험」으로 남긴다. 사실을 만들어 판정을 올리지 않는다.

재판정을 마치기 전에 낸 판정은 보고에서 「재판정 전」이라고 밝힌다.

## 보고

- 보고는 SKILL.md 「보고 형식」대로 단계 완료표를 먼저 보인다(구직 사이트 글은 「검토 범위」 표대로 한다).
- 결과는 세 가지로 나눠 보인다([panel/공통.md](panel/공통.md) 「결과의 세 분류」): 고치면 풀리는 것(프로필에 있는 사실로 칸을 고치면 풀림), 물으면 풀리는 것(G 질문), 글로 풀리지 않는 격차(프로필에 없는 경력·요건, 면접 준비나 전략으로 넘김).
- 「통과」는 직무 전문가와 인사 담당자의 H가 모든 칸 「예」이고, 탈락 사유 점검에 풀리지 않은 걸림이 없으며, ⑧ 재판정을 마쳤을 때만 보고한다. 못 넘은 조건과 그 칸을 사용자에게 먼저 알리고, 제출 여부는 사용자가 정한다.
- 판정은 서류 품질에 대한 판단이고 합격 확률이 아니다. 보고할 때 함께 적는다.
- 최종본과 함께 맞춤 결정을 추려 보여 준다(몇 개인지는 그 서류가 정하고 심사하지 않는다): 무엇을 앞세웠고 왜, 넣은 회사 각도, 검토에서 가장 크게 바뀐 것, 역할 사이에 갈린 제안, 면접으로 넘긴 격차. 반영한 제안과 건너뛴 제안도 보여 준다. 최종 결정은 사용자가 한다.
- 역할별 검토 결과(A, C, D)와 반영한 문장, E 메모의 처리를 `applications/<회사>-<직무>/검토.md`에 남긴다(면접 준비에서 쓰는 법은 [interview.md](interview.md) 「질문 예측」).

## 부를 때 넘길 것

기본 검토, ⑥, ⑦과 대결에 같이 쓴다.
- 역할: [panel/공통.md](panel/공통.md) 「역할 나누기」의 역할 이름 하나, 기본 검토면 「인사 담당자(기본 검토)」. 직무 전문가에게는 지원 공고의 직무를 넘기고(공고가 없는 서류는 그 서류가 겨냥한 직무) 사용자의 목표 직무를 고정해 넘기지 않는다. 서류 하나가 두 직무에 지원하거나 이력서가 여럿이면 직무·이력서마다 따로 부른다. 지원 회사의 업종은 넘기지 않는다(회사 맞춤은 기업 분석 [company.md](company.md)과 인사 담당자가 맡는다).
- 초안 파일 경로, 문서 종류(국문 이력서 / 경력기술서 / 자소서 / 영문 CV / 커버레터 / 사이트 소개글), 서류 상태(작업본 / 제출본)
- 초안의 문장 수: 메인 대화가 센다. 세는 규칙은 [panel/공통.md](panel/공통.md) 「문장 세기」를 따른다
- 공고 원문 경로(`postings/…`), 기업 분석 경로(있으면 지원 파일 `기업분석.md`와 회사 파일 `work/회사/<회사>/회사분석.md` 둘 다)
- 지원 폴더의 `전략.md` 경로(있으면). 인사 담당자(기본 검토 포함)에게만 넘긴다
- 프로필 경로: `profile/profile.md`와 경험 카드(`profile/stories/`, 목록은 `profile/stories.md`)
- 지원 직무의 직무 프로필 경로(`work/직무분석/<직무>.md`, [job-analysis.md](job-analysis.md)). 모든 역할에 넘긴다. 부르기 전에 프로필이 있고 job-analysis.md 「쓸 때」의 완성 기준을 채웠는지 확인하고, 아니면 먼저 만들거나 채운다
- 역할의 지식 파일 경로: 역할별 `panel/지식-<역할>.md`와, 국어·영어 교정·지원자 본인을 뺀 역할에는 `panel/지식-채용실무.md`. 직무 전문가에게는 `panel/지식-직무.md`와 공고 직군의 `work/검토단-근거/지식-직무-<직군>.md`를 넘긴다. 부르기 전에 그 직군의 파일이 있는지 확인하고, 없으면 [job-analysis.md](job-analysis.md) 「직군 지식 파일 확인」대로 먼저 만든다.
- ⑥의 두 역할에는 `배정표.md`, `작성기록.md`, 문체 기준 [style-essay.md](style-essay.md), `profile/본보기/`의 원문 경로를 더 넘긴다. 모든 역할에 문체 기준과 카드의 「⑤ 사용자의 말」·「⑦ 경계」를 읽게 한다
- 사용자 확정 문구 파일(경력란 확정본, `profile/경력기술서-기준본.md`)이 있으면 경로
- 이미 물은 질문의 답변안 파일과 대외비·서류 사용 금지 사실 목록(있으면). 검토 에이전트는 이 질문을 G에 다시 내지 않고 금지 사실을 대안 문장에 쓰지 않는다
- 프로필 「자기 이해」의 이직 서사와 공통 축(인사 담당자에게)
- 공고가 없으면(사이트 소개글 등) 가상 인물로 삼을 독자: 그 서류가 겨냥한 직무(지원 직무)의 채용 담당자·헤드헌터. 공개 공간에 올라가는 글이면 그 사실도 넘긴다
- 검토 에이전트에는 쓰기 도구가 없으므로 파일 저장을 지시하지 않는다. 역할마다 새 에이전트를 띄우고 한 에이전트에 두 역할을 맡기지 않는다
- 기준 파일과 이 스킬의 문서가 부딪치면 스킬 문서를 따른다. 기준 파일을 고치는 절차는 [panel/유지보수.md](panel/유지보수.md)에 있다.

## 한 판

한 판은 사용자 피드백을 받아 문장을 새로 쓴 초안 하나다. 같은 판 안에서 검토 결과를 반영해 고치는 일과 칸을 다시 쓰는 일은 그 판의 수정이다. 새 판은 사용자 피드백 뒤에만 시작한다.

## 바뀐 문장 다시 검토

마지막 검토 뒤에 문장이 바뀌면(사용자 수정, 검토 결과를 반영한 `job-writer`의 수정) ⑧의 재판정을 한다: 바뀐 칸만 검토 에이전트에 다시 맡기거나 메인 대화가 [checklist.md](checklist.md)로 다시 확인하고, 바뀌지 않은 칸은 다시 보지 않는다. 사용자가 직접 고친 글은 「검토 범위」대로 사실 대조와 글자 수만 확인한다. 제출 전에 이 확인을 마친다([submit.md](submit.md) 「순서」의 최종본 확인).

## 에이전트를 부를 수 없을 때

기본 검토는 메인 대화가 [checklist.md](checklist.md)를 직접 채우고, 네 역할 검토는 역할별 기준 파일로 역할마다 직접 검토한다. 스스로 쓴 글을 스스로 본 결과라 약하다고 사용자에게 알린다. `job-writer`를 부를 수 없으면 자소서 초안은 저장할 수 없으므로 멈추고 사용자에게 알린다.
