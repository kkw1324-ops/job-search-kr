# 지원 기록

`tracker.md` 한 파일에 표로 관리한다. 파일이 없으면 아래 머리글로 만든다.

```markdown
# 지원 기록
결과 확인 기간: <일 수>

| 번호 | 회사 | 직무 | 채널 | 상태 | 점수 | 지원일 | 마감일 | 다음 할 일 | 다음 할 날 | 폴더 | 메모 |
|---|---|---|---|---|---|---|---|---|---|---|---|
```

- 결과 확인 기간은 사용자가 정한 값이다. 비어 있으면 처음 필요할 때 한 번 묻고 적는다.
- 채널: 사람인, 원티드, 리멤버, 잡코리아, 회사 채용 페이지, 추천, 헤드헌터, 공공기관 등
- 날짜는 YYYY-MM-DD
- 칸 안에 `|`와 줄바꿈을 쓰지 않는다. 긴 내용은 지원 폴더의 파일에 쓰고 메모에는 한 줄만.
- 공고나 메일의 문장을 그대로 옮기지 않는다. 사용자가 확인한 사실만 짧게 쓴다.

## 상태

상태 칸에는 아래 값만 쓴다. 날짜, 괄호 설명, 권고 같은 꾸밈을 넣지 않는다. 그런 내용은 메모 칸에 쓴다.

| 상태 | 뜻 |
|---|---|
| 평가함 | 공고 평가만 함 |
| 지원안함 | 평가 뒤 사용자가 지원하지 않기로 함 |
| 준비중 | 서류 작성 중 |
| 지원함 | 제출을 확인함 |
| 서류통과 | 서류 합격 연락 |
| 필기·과제 | 인적성, NCS 필기, 코딩테스트, 과제, AI역량검사 진행 |
| 1차면접 | |
| 2차면접 | |
| 최종면접 | 임원 면접 등 |
| 처우협의 | 오퍼·연봉 협의 |
| 합격 | 입사 확정 |
| 불합격 | 회사가 탈락 통보 |
| 무응답 | 후속 연락 두 번 뒤에도, 또는 60일 넘게 변화 없이 소식 없음. 사용자가 승인해 바꾼다 |
| 포기 | 준비하거나 지원한 뒤 사용자가 접음 |
| 오퍼거절 | 사용자가 오퍼를 거절함 |

규칙:
- "지원함"은 사용자가 제출했다고 말했거나, [submit.md](submit.md)대로 제출한 뒤 접수 완료 화면이나 지원 내역 페이지에서 접수를 확인했을 때만 쓴다. 지원일은 실제 제출 날짜로 쓴다. 다음 할 일은 「결과 확인」, 다음 할 날은 지원일에 결과 확인 기간을 더한 날로 쓴다. 다른 대화나 에이전트가 제출했다고 보고한 것은 사용자에게 제출 여부를 확인한 뒤 쓴다.
- "지원안함"은 사용자가 지원하지 않기로 말했을 때만 쓴다. 평가 보고서의 권고만으로 바꾸지 않는다.
- 상태를 뒤로 되돌리지 않는다. 잘못 적었으면 메모에 정정 이유를 쓴다.
- 합격, 불합격, 무응답, 포기, 오퍼거절, 지원안함은 끝난 상태다. 같은 회사에 다시 지원하면 새 행을 만든다. 두 번째 이상 지원이면 회사 채용 사이트에 남은 예전 지원서와 지금 서류가 어긋나지 않는지 확인하라고 사용자에게 알린다.
- 새 행을 만들기 전에 같은 회사·직무 행이 다른 채널(직접 지원, 다른 헤드헌터)로 있는지 본다. 있으면 어느 채널로 갈지 사용자가 정한다. 한 자리에 두 채널로 들어가면 양쪽에서 신뢰를 잃는다.
- 메일이나 문자 내용을 붙여넣어 상태를 바꿀 때는 사용자에게 한 번 확인한다. 발신자가 회사나 채용 시스템인지 사용자에게 묻고, 확인되지 않으면 바꾸지 않는다.

## 후속 연락

| 상태 | 첫 연락 | 이후 | 최대 |
|---|---|---|---|
| 지원함 | 지원 7~10일 뒤 | 7일마다 | 2회, 그 뒤 무응답 |
| 서류통과~최종면접 | 연락 받은 날 안에 회신 | 3일마다 | 제한 없음 |
| 면접 뒤 | 다음 날 감사 메시지(외국계는 흔함, 국내 기업은 선택) | 결과 예정일이 지나면 1회 | |

- 첫 메일: 제목 → 직무와 지원일 → 내가 줄 가치 하나(수치) → 이 회사에 맞춘 사실 하나 → 가볍게 진행 상황 문의와 통화할 수 있는 때. 150단어(한국어 400자) 이하. "혹시나 해서 연락드립니다" 같은 말은 쓰지 않는다.
- 내용은 제출한 서류와 기업 분석에 있는 것만 쓴다. 서류에 없는 경력·수치를 새로 넣지 않는다.
- 헤드헌터를 거친 지원은 후속 연락을 헤드헌터에게 한다. 고객사를 모르면 회사 이름을 물어보라고 권한다. 알게 되면 회사 칸을 고치고 같은 회사 행이 있는지 다시 본다.
- 두 번째는 다른 각도로 쓴다. 세 번째는 쓰지 않고, 무응답 처리·다른 연락처·우선순위 낮추기 중 사용자가 고른다.
- 메일·메시지는 초안만 쓴다(SKILL.md 규칙 5). 사용자가 보냈다고 확인한 연락만 기록한다.
- 국내 공채는 결과 발표일이 정해져 있다. 발표일 전에는 후속 연락을 권하지 않는다.

## 여러 곳 지원 계획

평가한 공고가 여럿이면 기업 분석 전에 계획 표를 `work/지원계획.md`에 만든다.
- 목표 건수와, 겹치지 않게 나눈 마감 구간으로 표를 만든다.
- 목표 건수를 정할 때 참고 서류 합격률로 계산한 기대 합격 건수를 함께 보인다. 참고 합격률은 공개 통계 같은 조사 자료에서 가져오고, 그 값의 대상(신입·경력)을 함께 적는다. 자료에 없으면 적지 않는다.
- 작성·제출 순서를 정한다. 회사 홈페이지 접수 공고는 [submit.md](submit.md) 「미리 할 것」을 순서에 넣는다.
- 제출 목표일을 마감일보다 앞에 둔다. 마감일에 내면 본인인증, 첨부 오류, 사이트 장애를 고칠 시간이 없다.
- 같은 직무·공고 유형은 [strategy.md](strategy.md)의 묶음 전략으로 묶는다.

## 대화를 시작할 때

사용자가 지원 현황을 묻거나 구직 작업을 시작하면 대화마다 처음 한 번 오늘 날짜 기준으로 알려 준다.
- 마감이 7일 안에 남은 "평가함", "준비중". 마감이 이미 지난 "준비중"은 따로 한 줄로 알린다
- "다음 할 날"이 지났거나 오늘인 행
- 그 가운데 다음 할 일이 「결과 확인」인 "지원함" 행: 지원 내역 페이지나 메일에서 결과가 왔는지 확인하자고 한 줄로 제안한다. 불합격을 알리지 않는 회사가 많으므로, 결과가 없으면 「후속 연락」 표대로 연락할지 사용자가 정한다. 아래 60일 항목에도 해당하면 60일 항목만 쓴다
- "지원함"부터 "처우협의"까지의 상태로 60일 넘게 변화 없는 행: 한꺼번에 무응답으로 정리할지 사용자에게 묻는다(전부 / 골라서 / 그대로). 제출하지 않은 "평가함", "준비중"은 넣지 않는다
- 프로필 「행동으로 드러난 선호」의 분석일 뒤에 지원일이 적힌 행이 있으면, 그 절을 다시 볼지 한 줄로 묻는다([profile.md](profile.md) 「행동으로 드러난 선호」)

## 결과 기록

- 회사에서 받은 피드백은 해석하지 않고 들은 그대로 지원 폴더의 `결과.md`에 추가한다. 이전 기록은 고치지 않는다.
- 결과를 기록할 때 도달한 전형 단계와 날짜를 적는다. 한두 가지만 묻는다: 회사가 무엇을 중요하게 본 것 같은지, 다음에 무엇을 다르게 할지. 답은 들은 그대로 적는다.
- 제출한 서류는 지원 폴더에 그대로 둔다. 보관한 파일이 곧 제출본이다.
- 공고를 기억으로 다시 만들지 않는다. `postings/`의 원문을 쓴다.
