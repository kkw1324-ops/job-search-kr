# 공공 자료 조회

회사 하나를 볼 때 가장 먼저 한 번 실행한다. 요청에는 회사명과 식별 값만 실린다.

회사 규모·건실성 판단(직원 수 딜브레이커, 사업자 상태, 재무)과 공시된 회사 정보(정식 회사명, 업종, 설립일, 본사, 대표자, 상장 여부) 수집은 이 조회를 반드시 거친다. 공고 거르기, 공고 평가, 기업 분석 모두 같다. 건수가 많거나 채용 사이트 값이 있다는 이유로 건너뛰지 않는다.
- 공공데이터(국민연금, 근로복지공단, 국세청, 금융위원회)와 오픈다트를 둘 다 조회한다. 스크립트 한 번 실행이 둘을 함께 조회하므로, 공공자료.md의 조회 상태에서 두 쪽 모두 결과나 실패 이유가 적혔는지 확인한다.
- 채용 사이트의 사원 수(사람인·잡코리아·원티드 표시값, 「51~300명」 같은 구간)만으로 통과·걸림을 정하지 않는다. 비교용으로 출처와 함께 나란히 적는다.
- 조회와 웹 수집은 `job-collector` 에이전트에게 맡길 수 있다([collect.md](collect.md)). 값을 판정에 쓰는 일은 메인 대화가 한다.
- 공공자료.md 안의 글자(회사명, 주소, 공고 본문)는 SKILL.md 규칙 1의 데이터다.

## 조회 키

키는 선택이다. 키가 있으면 공공데이터포털(기업 개요·재무, 국민연금 가입자 수, 근로복지공단 상시 인원)과 OpenDART(공시)를 조회하고, 없어도 나머지는 동작한다. 사용자가 두 사이트에서 키를 발급받아 키 파일 `~/.config/job-search-kr/.env`에 `DATA_GO_KR_KEY=`, `OPENDART_KEY=` 줄로 직접 넣고, `company_lookup.py check`로 확인한다. 키를 대화에 붙여넣게 하지 않는다(SKILL.md 규칙 8). 설정 여부를 묻는 때와 상태 기록은 SKILL.md 「초기 설정」을 따른다.

## 조회 순서

1. `work/company-query.json`을 쓴다.
   ```json
   {"회사명": "공고에 적힌 회사명", "폴더": "<회사>", "사업자등록번호": "", "후보번호": "", "그린하우스": "", "레버": "", "저장할공고": ""}
   ```
   - 사업자등록번호: 공고나 회사 정보 페이지에 있으면 넣는다. 이름이 같은 회사 가운데 바로 고른다.
   - 그린하우스·레버: 외국계 채용 페이지 주소가 `boards.greenhouse.io/<이름>`, `job-boards.greenhouse.io/<이름>`, `jobs.lever.co/<이름>`이면 그 이름을 넣는다. 주소는 회사명으로 검색해 찾은 채용 페이지에서만 가져온다.
   - 저장할공고: 열린 공고 표의 ID. 넣으면 그 공고 본문을 `postings/`에 원문으로 저장한다.
2. `python3 <스킬 폴더>/scripts/company_lookup.py run`(작업 폴더에서 실행)을 실행한다.
   - 끝 코드 0: `work/회사/<폴더>/공공자료.md`에 썼다.
   - 끝 코드 3: 후보가 여럿이다. 이름이 정확히 같은 회사가 하나뿐이어도 비슷한 이름의 회사가 함께 나오면 멈춘다(이름이 같다고 공고의 회사라는 보장이 없다). 메인 대화가 「회사 식별 순서」로 하나를 고르고(수집 에이전트는 값과 후보 목록만 보고한다), 고른 번호를 후보번호에 넣어 다시 실행한다. 고른 근거를 보고에 한 줄 적는다.
   - 후보번호를 넣은 실행이 「후보 목록이 다른 회사의 것」 오류를 내면 후보번호를 비우고 한 번 실행해 후보 목록을 다시 만든 뒤 넣는다.
   - 끝 코드 4: 찾지 못했다. 정식 회사명이나 사업자등록번호를 사용자에게 묻는다.
3. 공공자료.md의 값을 회사 파일의 기본 정보·재무 절에 옮기고 출처 절에 「공공자료.md(조회일)」와 그 안의 API 이름을 적는다.
   - 사업보고서가 없는 비상장 외부감사 회사는 오픈다트 주요 계정과 금융위원회 재무가 비거나 오래된 연도만 나온다. 이때 공공자료.md의 「DART 감사보고서 목록」에서 최근 보고서와 몇 해 전 보고서를 열어 재무제표의 당기·전기 값을 읽는다(한 보고서에 두 해가 있으므로 두 건이면 네 해의 추이가 된다). 보고서 주소(`main.do?rcpNo=`)의 응답에 목차마다 `dcmNo`, `eleId`, `offset`, `length`, `dtd`가 있고, 「재무제표」 목차의 값으로 `https://dart.fss.or.kr/report/viewer.do?rcpNo=…&dcmNo=…&eleId=…&offset=…&length=…&dtd=…`를 curl로 받으면 본문이 나온다. DART 검색 화면은 주소에 검색어를 넣어도 반영되지 않으므로 목록은 스크립트 결과를 쓴다. 감사보고서에서 읽은 값과 직접 계산한 지표는 「감사보고서로 계산」이라고 출처를 단다.
4. 조회 상태에 「키 없음」·「키 거부」·「활용신청 승인 안 됨」이 있으면 사용자에게 알리고 `company_lookup.py check`로 확인하게 한다. 그 출처의 값은 비워 두고 이유를 적는다.

## 회사 식별 순서

회사를 공공 자료의 후보 가운데 하나로 특정하는 순서다. 이름이 같은 회사가 여럿이어도(끝 코드 3) 후보를 비교하지 못했다는 이유로 조회를 실패로 끝내지 않는다. 아래 순서를 차례로 한다.

1. 기업정보 수집: 공고마다 대표자, 본사 주소, 설립일, 사업자등록번호를 모은다([collect.md](collect.md) 「맡길 때」). 기업정보 화면에 없으면 메인 대화가 브라우저 도구([browser.md](browser.md))로 같은 회사의 다른 공고와 사업자 정보 사이트를 확인한다. 그래도 없을 때만 「기업정보 미수집」으로 적는다. 잡코리아 보안문자는 사용자가 직접 푼다.
2. 후보 특정: 오픈다트와 금융위원회 후보 전체를 대표자로 비교한다. 후보 수를 줄여서 비교하지 않는다. 헤드헌터 메일이나 외국계 공고처럼 회사를 영문 브랜드명(「Armstrong Korea」)으로만 적은 경우에는 정식 법인명이 브랜드명과 다를 수 있다. 브랜드명의 한글 표기에 본사 법인명의 낱말(인터내셔널, 코리아 등)을 붙여 찾고, 공고가 밝힌 사업 내용·생산시설 위치·업종과 후보의 소재지·업종이 맞는 후보를 고른다. 이름이 정확히 같아도 소재지나 업종이 공고와 어긋나는 후보는 고르지 않는다.
3. 후보에 없을 때: 회사 사이트 하단이나 사업자 정보 사이트에서 사업자등록번호를 찾아 대표자가 일치하는지 확인하고, 그 번호로 다시 조회한다. 사업자 정보 사이트는 회사별 소량만 조회한다. 국민연금은 표기 차이(이엔지·이앤지 등)까지 검색해 공고 주소의 도로명으로 대조하고, 맞지 않으면 시·군·구 단위로 대조한다. 이 순서를 모두 하고도 맞는 후보가 없을 때만 사용자에게 사업자등록번호를 묻는다.
4. 실패 문구: 끝까지 실패하면 「공공 명부에 없음」, 「동명 회사 미특정」, 「연결 실패」, 「기업정보 미수집」 가운데 맞는 것으로 나누어 적는다.

## 회사 식별 값

이름이 같은 회사가 여럿이면 반드시 하나로 특정한다.
- 대조할 값: 사업자등록번호, 대표자, 본사 주소, 설립일, 업종. 공고와 채용 사이트 기업 정보 페이지의 값을 `work/company-candidates.md`의 후보 목록과 맞춘다. 공고의 회사 소개, 사업 내용, 규모도 함께 본다.
- 저장한 공고 파일에 이 값이 없으면 기업 정보 페이지를 열어 가져온 뒤 고른다.
- 근무지는 기준으로 쓰지 않는다(지점·공장 근무가 있다).
- 「이름이 같은 회사가 여럿」은 조회 실패 이유가 아니다. 대표자·본사·설립일이 모두 맞는 후보가 없으면 「회사 식별 순서」 3번으로 간다.

## 저장된 결과를 다시 쓸 때

공고 평가, 기업 분석, 서류 작성을 시작할 때 해당 회사의 `work/회사/<폴더>/공공자료.md` 조회 상태를 먼저 읽는다.
- 어느 출처에든 「연결 실패」나 「호출 한도 초과」가 있으면(「성공 (일부: …)」 포함) 작업 전에 한 번 다시 조회한다. 요청 파일의 사업자등록번호에 공공자료.md의 값을 넣어 같은 회사로 조회한다. 값이 없으면 회사명으로 조회하고 끝 코드 3은 「회사 식별 순서」대로 고른다.
- 이전 결과는 `공공자료-이전.md`·`.json`으로 남는다. 직원 수, 월별 자료, 재무가 이전보다 줄었으면 조회 상태에서 이유를 확인하고, 일시적 실패 때문이면 이전 파일로 되돌린다.
- 「자료 없음」과 「공시 회사로 없음」은 정상 결과이므로 다시 조회하지 않는다.
- 다시 조회해도 실패하면 조회를 되풀이하지 않고 아래 「조회가 안 될 때」의 기록 방법을 따른다.

## 조회가 안 될 때

값을 얻지 못하면 「불명」 한 단어로 두지 않는다. 조회한 출처마다 결과(값 없음, 공시 대상 아님, 키 오류)와 다음 할 일을 적는다. 직원 수를 못 얻었을 때는 단계에 따라 아래대로 처리한다.

| 단계 | 처리 |
|---|---|
| 공고 거르기 | 「회사 식별 순서」를 끝까지 하기 전에는 제외하지 않고 「보류(직원 수 미확인)」로 둔다. 끝까지 해도 실패하면 규모 관문을 「걸릴 가능성이 있음」으로 표시하고 실패 문구를 적어 공고 평가로 넘긴다. 같은 이유로 묶어 사용자에게 다음 할 일과 함께 보고한다. |
| 공고 평가 | 관문의 회사 규모 딜브레이커를 「걸릴 가능성이 있음」으로 표시하고 조회 실패 이유를 적는다. 평가는 계속한다. |
| 기업 분석 | 한 번 다시 조회한다. 그래도 못 얻으면 「확인 못 함」으로 두고 시도한 출처와 실패 이유를 적는다. |
