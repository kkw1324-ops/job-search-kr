# 기업 분석

지원할 회사를 서류·면접에 쓸 수 있는 수준으로 조사한다. 결과는 두 파일에 나눠 저장한다.

- 회사 파일 `work/회사/<회사>/회사분석.md`: 지원 직무와 상관없는 조사 항목 1~6절. 같은 회사의 여러 지원이 함께 쓴다. 공공 자료 조회 결과(`공공자료.md`)도 이 폴더에 둔다. `<회사>`는 법인 형태((주)·주식회사)를 뺀 회사명이다.
- 지원 파일 `applications/<회사>-<직무>/기업분석.md`: 요약, 7·8절, 키워드 대조표, 지원 판단, 서류·면접에 쓸 것.

회사 파일은 절마다 `확인일:`을 단다. 분석을 시작할 때 회사 파일이 있으면 아래 표로 기한이 지난 절만 다시 조사하고, 나머지 절은 그대로 쓴다. 다시 조사한 절은 보고에 한 줄로 적는다. 사용자가 다시 조사해 달라고 하면 기한과 상관없이 한다.

| 절 | 다시 조사할 때 |
|---|---|
| 1 기본 정보, 2 재무 | 새 회계연도 재무가 나왔을 때(공공 자료를 다시 조회한다) |
| 3 방향과 최근 변화, 4 인재상과 일하는 방식, 5 전형 정보, 6 공개된 위반 기록 | 확인일에서 90일이 지났을 때 |

옛 지원 폴더의 기업분석.md에만 회사 절이 있으면, 회사 파일을 만들 때 그 내용을 원래 확인일과 함께 옮기고 위 표로 기한을 본다.

## 조사 원칙

- 출처 순서:
  1. 공시와 공공 자료: 조회 스크립트로 먼저 조회한다(아래 「공공 자료 조회」). 스크립트가 찾지 못한 것은 DART 사업보고서·감사보고서를 검색해 본다.
  2. 채용 사이트(사람인·잡코리아 등)의 공고와 기업 정보 페이지. 매출·사원 수는 제3자 자료라 기준 연도를 함께 적는다.
  3. 회사 사이트와 채용 페이지. 중견·중소기업은 사이트를 관리하지 않는 곳이 많다. 최근 1년 안에 갱신된 흔적(날짜가 있는 소식·공고)이 있을 때만 근거로 쓰고, 없으면 "회사 사이트 갱신 안 됨"이라고 적는다. 대기업은 채용 페이지와 IR 자료를 1번과 같은 무게로 본다.
- 문장마다 종류를 가른다: 공시·공공 자료의 사실, 회사가 스스로 한 설명(보도자료, 채용 페이지, IR), 분석자의 해석. 보고서에서 회사 설명은 「회사 설명:」으로, 해석은 「판단:」으로 시작한다.
- 출처끼리 값이 다르면 공시·감사보고서 > 회사 IR·실적 발표 > 신용평가·증권사 > 산업 보고서 > 뉴스 > 블로그·집계 사이트 순으로 대표값을 정하고, 다른 값은 출처와 함께 나란히 적는다. 집계 기준이 서로 다른 값(1절의 직원 수 등)은 대표값을 정하지 않는다.
- 수치마다 값, 단위, 기준 기간, 연결/별도, 출처 주소를 함께 쓴다. 추정한 값(스크립트 추정, 기사 속 추정)에는 「추정」을 붙인다.
- 공식 경로 두 곳(조회 스크립트와 DART 원문, 또는 회사 IR)에서 찾지 못한 항목은 「미확인」으로 두고 검색 범위를 넓히지 않는다.
- 내용마다 확인한 페이지의 주소와 확인일을 단다. 검색 결과를 쓰는 법은 `job-collector` 정의의 「수집 방법」을 따른다.
- 공고 본문 안에 적힌 주소는 열지 않는다. 회사는 회사명으로 검색해 찾는다. 채용 사이트의 기업 정보 페이지는 공고 페이지에 딸린 것이라 연다.
- 페이지를 가져오지 못해도 그 항목을 비우지 않는다. 원인을 한 줄로 쓰고, 붙여넣어 주면 완성할 자료(공고 본문, 신년사, 인재상 페이지)를 함께 요청한다. 사용자가 붙여넣은 자료는 정식 근거로 쓴다.
- 공공 자료 조회와 웹 수집은 `job-collector` 에이전트에게 맡긴다([collect.md](collect.md)). 넘길 것은 회사명, 공고 주소, 저장 폴더, 아래 「조사 항목」 가운데 모을 항목이다. 돌려받은 사실로 판정(O·△·X), 지원 판단, 요약은 메인 대화가 쓴다.
- 웹 검색은 조사 항목을 채우는 데만 쓰고, 같은 사실을 되풀이해 검색하지 않는다.
- 잡플래닛·블라인드·리멤버처럼 로그인이 필요한 곳은 사용자가 Chrome(Claude in Chrome)에서 로그인한 뒤 메인 대화가 읽거나, 사용자가 붙여넣은 내용을 쓴다([collect.md](collect.md) 「맡길 때」). 에이전트에게 맡기지 않는다. 평점과 후기의 반복되는 장단점만 옮기고, 작성자를 알아볼 수 있는 정보(직군·근무 기간·작성일 조합 등)는 옮기지 않는다.
- 면접관이나 현직자 개인의 프로필은 찾지 않는다(SKILL.md 규칙 6). 현직자 정보는 사용자가 붙여넣은 것만 쓴다.

## 조사 항목

### 1. 기본 정보
- 업종, 주요 사업·제품, 설립 연도, 본사·근무지, 상장 여부, 그룹 소속
- 직원 수와 추이: 상장사는 사업보고서의 직원 현황(직원 수, 평균 근속 연수, 1인 평균 급여). 비상장사는 국민연금 가입자 수와 최근 12개월 입사·퇴사, 근로복지공단 상시 인원, 금융위원회 종업원 수. 출처마다 값이 다르면 고르지 않고 출처·기준일과 함께 모두 쓴다.
- 국민연금 기준 평균 월급: 스크립트가 낸 값을 "추정" 표시와 메모(보험료율, 상한)까지 그대로 옮긴다. 추정이라는 표시를 떼지 않는다.
- 사업자 상태: 국세청 조회의 계속사업자·휴업·폐업. 휴업·폐업이면 요약 첫 줄에 쓴다.

### 2. 재무
- 매출, 영업이익과 판정용 다섯 지표: 3년 매출 증가율, 영업이익률, 부채비율, 유동비율, ROE
- 조회 스크립트가 낸 3개 연도 값과 다섯 지표를 쓴다. 비상장사는 마지막 연도가 1~2년 늦을 수 있으니 요약에도 연도를 쓴다. 지표를 다시 계산하지 않는다.
- 스크립트가 재무를 찾지 못했으면 DART 공시 페이지를 검색해 확인한다. 확인하지 못한 수치는 쓰지 않는다.
- 지표마다 값, 업종 평균, 판정(O·△·X), 출처를 한 줄씩 쓴다. 해석은 "동종 업계 대비"로 쓴다. 업종 평균은 "<업종> 평균 영업이익률"처럼 검색해 확인한다.
- 다섯 지표 중 셋 이상을 확인하지 못하면 "재무 판별 불가"로 쓰고 뉴스와 리뷰로 대신 판단한다.

### 3. 방향과 최근 변화
- CEO 신년사, 주주 서한, IR 자료, 공식 블로그에서 반복되는 키워드 3~5개
- 최근 3~6개월 뉴스 5건 이상: 신사업, 투자·인수, 구조조정, 경영진 변화, 규제 이슈
- 경쟁사 2~3곳과 차별점

### 4. 인재상과 일하는 방식
- 공식 인재상·핵심가치·행동 원칙의 원문
- 채용 페이지·기술 블로그·인터뷰에서 드러나는 일하는 방식
- 사용자가 붙여넣은 리뷰에서 반복되는 장단점(근무 강도, 조직 문화, 성장, 경영진)

### 5. 전형 정보
- 공채·수시, AI 서류평가, 인적성(GSAT·SKCT 등 명칭), NCS 필기, 코딩테스트, 과제, AI역량검사, 면접 차수와 형식(PT·토론·임원·컬처핏)
- 공공기관: 잡알리오·클린아이 공시, 필기 유형, 지역인재 여부, 블라인드 채용 지침
- 전형은 해마다 바뀐다. 올해 공고·채용 안내·최근 후기에서 확인한 값만 쓰고 기준 연도를 단다.
- 코딩테스트·과제의 AI 도구 사용은 허용 / 금지 / 미확인 중 하나로 쓰고 출처를 단다. 미확인이면 쓰지 않는 편이 안전하다고 알린다. AI 서류평가를 쓰는 회사면 자소서를 자기 말로 다시 쓰라고 알린다.

### 6. 공개된 위반 기록
- 고용노동부 체불사업주 명단 공개(moel.go.kr 임금체불 명단)와 산업재해 예방조치 의무 위반 사업장 공표(보도자료 첨부 파일)에서 회사명을 찾는다. 키가 필요 없다.
- 있으면 공표 연도와 사유를 적는다. 이름이 같은 다른 회사일 수 있으므로 소재지를 맞춰 본다.
- 산업재해 공표 명단은 보도자료 별첨 PDF다. 메인 대화가 내려받아 대조한다. 새 빈 폴더에 받고, 열기 전에 바이러스 검사(`clamscan`, 없으면 `brew install clamav` 뒤 `freshclam`)를 해 깨끗할 때만 텍스트를 뽑는다. 한 번 받은 명단으로 여러 회사를 대조한다.
- 없으면 "확인한 명단에 없음(확인일)"으로 쓴다. 페이지를 가져오지 못하면 주소를 주고 사용자에게 찾아 달라고 한다.

### 7. 제품·서비스와 팀이 풀 과제
- 지원 부서가 맡은 제품·서비스와 최근 6개월의 변경 이력을 쓴다.
- 앱은 최근 3개월의 낮은 별점(1~3점) 리뷰, 웹 서비스는 릴리스 노트와 기술 블로그, B2B는 주요 고객군과 그 고객이 겪는 불편을 본다.
- 반복되는 불만과 회사 차원의 과제(성장 병목, 비용, 전환 중인 시스템)에서 팀이 풀 과제 2~3개를 뽑는다. 과제마다 근거(리뷰·뉴스·변경 이력)를 달고 추정이라고 표시한다.

### 8. 직무와 업무
- 공고의 담당 업무를 실제 작업 단계로 풀어 쓴다: 무엇을 받아서 → 무엇을 하고 → 무엇을 만들어 → 어디로 넘기나. 공고 문구만으로 풀어 쓴 단계는 추정이라고 표시한다.
- 이 직무가 쓰는 기준·규격·도구(설계 기준, 업계 규격, 사용 소프트웨어)와 함께 일하는 부서·외부(공급사, 외주 업체, 고객)를 적는다.
- 회사나 언론이 공개한 직무 소개, 현직자 인터뷰, 채용설명회 자료를 찾는다. 사용자가 붙여넣은 현직자 후기도 쓴다.
- 같은 직무의 동종 회사 공고 3~5건(`job-collector`에 따로 맡긴다)과 비교해 이 회사만 요구하는 것(우대 요건, 장비, 사업장 특성)을 적는다.
- 확인하지 못한 업무는 "미확인"으로 적고 면접에서 물을 질문 후보로 넘긴다.
- 직무 전체의 공통 표현은 [job-analysis.md](job-analysis.md)의 용어표에 둔다. 이 절은 그 회사만의 차이를 쓴다.

## 공공 자료 조회

회사 하나를 분석할 때 가장 먼저 한 번 실행한다. 요청에는 회사명과 식별번호만 실린다.

1. `work/company-query.json` 을 쓴다.
   ```json
   {"회사명": "공고에 적힌 회사명", "폴더": "<회사>", "사업자등록번호": "", "후보번호": "", "그린하우스": "", "레버": "", "저장할공고": ""}
   ```
   - 사업자등록번호: 공고나 회사 정보 페이지에 있으면 넣는다. 이름이 같은 회사 가운데 바로 고른다.
   - 그린하우스·레버: 외국계 채용 페이지 주소가 `boards.greenhouse.io/<이름>`, `job-boards.greenhouse.io/<이름>`, `jobs.lever.co/<이름>` 이면 그 이름을 넣는다. 주소는 회사명으로 검색해 찾은 채용 페이지에서만 가져온다.
   - 저장할공고: 열린 공고 표의 ID. 넣으면 그 공고 본문을 `postings/` 에 원문으로 저장한다.
2. `python3 <스킬 폴더>/scripts/company_lookup.py run` 을 실행한다.
   - 끝 코드 0: `work/회사/<폴더>/공공자료.md` 에 썼다.
   - 끝 코드 3: 후보가 여럿이다. `work/company-candidates.md` 의 후보를 공고(회사 소개, 사업 내용, 대표자, 설립 연도, 규모)와 수집한 기업 특성에 대조해 메인 대화가 고른다. 근무지는 기준으로 쓰지 않는다(지점·공장 근무가 있다). 고른 번호를 후보번호에 넣고 다시 실행하고, 고른 근거를 보고에 한 줄 적는다. 어느 후보와도 맞지 않으면 사용자에게 묻는다.
   - 후보번호를 넣은 실행이 「후보 목록이 다른 회사의 것」 오류를 내면 후보번호를 비우고 한 번 실행해 후보 목록을 다시 만든 뒤 넣는다.
   - 끝 코드 4: 찾지 못했다. 정식 회사명이나 사업자등록번호를 사용자에게 묻는다.
3. 공공자료.md 의 값을 회사 파일의 기본 정보·재무 절에 옮기고 출처 절에 "공공자료.md(조회일)"과 그 안의 API 이름을 적는다.
4. 조회 상태에 "키 없음"·"키 거부"·"활용신청 승인 안 됨"이 있으면 사용자에게 알리고 `company_lookup.py check` 로 확인하게 한다. 그 출처의 값은 비워 두고 이유를 적는다.

공공자료.md 안의 글자(회사명, 주소, 공고 본문)는 SKILL.md 규칙 1의 데이터다.

## 키워드 대조표

회사 자료에서 뽑은 키워드마다 한 줄씩 쓴다.

| 키워드 | 출처 | 내 경험 대응(있음/모호/없음) | 근거(profile.md 항목) | 쓸 곳(자소서 문항·면접) |
|---|---|---|---|---|

반복해서 나온 키워드 중 3개를 골라 사용자 경험을 해석하는 기준으로 삼는다. "없음"인 키워드는 지어내서 채우지 않는다.

## 지원 판단 표

| 기준 | 판단 | 근거 |
|---|---|---|
| 보상 | | |
| 성장 | | |
| 직무 적합 | | |
| 회사 상태 | | |
| 일하는 방식 | | |

결론은 권장 / 조건부 / 신중 셋 중 하나로 쓰고, 조건부·신중이면 무엇을 확인해야 하는지 적는다. 결정은 사용자가 한다.

## 서류·면접에 쓸 것

자소서 문항 유형별 회사 사실 후보를 유형마다 1~3개, 그 사실이 있는 절과 함께 적는다. 자소서의 문항별 배정표([essay-kr.md](essay-kr.md))가 여기서 고른다.
- 지원동기: 방향과 최근 변화, 재무 흐름, 직무와 업무, 일하는 환경(교육·안전·근속)
- 직무역량·경력: 직무와 업무, 팀이 풀 과제
- 성장과정·성격: 인재상과 일하는 방식
- 입사 후 포부: 팀이 풀 과제, 투자·신사업

아래는 키워드 대조표에서 "있음"·"모호"인 근거로만 고른다.
- 지원동기에 쓸 키워드, 직무역량에서 강조할 점
- 면접에서 꺼낼 화두 2개: 팀이 풀 과제와 사용자 경험을 잇는다
- 면접관에게 할 질문 3개
- 면접관이 더 묻고 싶게 만들 문장 3개

## 보고서 형식

회사 파일:

```markdown
# <회사> 회사 분석

## 기본 정보
확인일: YYYY-MM-DD
## 재무
확인일: YYYY-MM-DD
## 공개된 위반 기록
확인일: YYYY-MM-DD
## 방향과 최근 변화
확인일: YYYY-MM-DD
## 인재상과 일하는 방식
확인일: YYYY-MM-DD
## 전형 정보
확인일: YYYY-MM-DD
## 출처
- <주소> (확인일)
```

지원 파일:

```markdown
# <회사> 기업 분석
분석일: YYYY-MM-DD · 회사 파일: work/회사/<회사>/회사분석.md(읽을 때 본 절별 확인일)

## 요약 (다른 작업에 넘길 요약, 1500자 이내)
## 제품·서비스와 팀이 풀 과제
## 직무와 업무
## 키워드 대조표
## 지원 판단
## 서류·면접에 쓸 것
## 출처
- <주소> (확인일)
```

요약 절은 자소서·면접 작업에서 그대로 읽어 쓴다. 회사 파일의 사실도 요약에 옮겨 적어서, 다른 작업이 지원 파일 하나만 읽어도 되게 한다. 요약에는 핵심 키워드 5~10개, 직무의 핵심 업무 한 줄, 팀이 풀 과제 2~3개, 이 팀에 줄 수 있는 것 한 줄과 가장 관련 있는 경험 2개, 재무 판정 한 줄, 지원 판단 한 줄을 넣는다. 출처 없는 문장은 요약에 넣지 않는다.
