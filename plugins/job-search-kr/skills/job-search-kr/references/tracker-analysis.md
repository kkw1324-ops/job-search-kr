# 지원 기록 분석

## 탈락 패턴 분석

사용자가 요청하면 한다. 지원일이 적힌 행(실제로 제출한 건)만 보고, "평가함", "준비중", "지원안함"은 세지 않는다. 건수가 적으면 패턴이 우연일 수 있다고 함께 말한다.
- 분석 전에 지원 폴더의 `제출서류/`와 지원 기록을 맞춘다. 제출본이 있는데 "지원함"이 아닌 행은 사용자에게 확인해 고친다.
- 분석 전에 [tracker.md](tracker.md) 「대화를 시작할 때」의 결과 확인을 먼저 한다. 답이 오지 않은 건은 거절로 세지 않는다.
- 결과를 나눈다: 긍정(서류통과 이상) / 진행 중 / 부정 / 무응답 / 포기. "지원안함"은 제출 건이 아니므로 따로 센다.
- 결과가 나온 건 중 긍정 비율을 먼저 보여 준다. 결과가 나온 건이 적으면 비율 대신 건수로 말한다. `work/지원계획.md`의 참고 합격률이 있으면 제출 건수로 계산한 기대 건수를 함께 보이고, 실제 건수가 기대 건수 근처면 패턴을 찾기 이르다고 말한다.
- 나눠 볼 것: 직무군, 회사 유형(대기업·중견·스타트업·외국계·공공), 채널, 근무 방식, 평가 점수 구간, 반복된 격차, 공고 성격과 지원 구분(`전략.md`), 대전제 정합(`평가.md` 관문), `전략.md`의 「내 위치」, 검토에서 되풀이된 지적(`검토.md`), 제출 시점(마감까지 남은 날).
- 채널별 차이는 원인으로 단정하지 않는다.
- 점수 구간별 서류 통과율을 보여 주고 판정한다: 점수가 결과를 구분함 / 차이 없음 / 거꾸로 / 표본 부족. 거꾸로면 점수가 높았는데 떨어진 건들을 함께 읽어 보자고 제안한다. 점수 기준을 자동으로 고치지 않는다.
- 면접 복기 파일(`면접복기-<차수>.md`)이 있으면 답이 구체적이었던 역량과 지원한 직무군을 비교한다. 강한 역량이 지원 직무와 다르면 목표 직무군을 바꿀지 사용자에게 묻는다. 사용자가 바꾸겠다고 하면 [job-explore.md](job-explore.md)로 후보를 다시 뽑는다. 분석 결과에 면접관 이름은 쓰지 않는다.
- 되돌리기: 원인마다 어느 단계(자기 분석, 산업·직무 고르기, 전략, 서류, 제출)의 문제로 볼지 적는다. 사용자가 동의한 것은 그 단계의 산출물(프로필, `전략.md`나 묶음 전략, 경력기술서 기준본, 지원 계획)에 바로 고친다. 프로필은 SKILL.md 규칙 4대로 고친다. 산업·직무 고르기의 문제로 보면 목표 분야를 짧게 해 보는 작은 실험(사이드 프로젝트, 강의, 단기 계약)을 선택지로 함께 보인다. 대전제를 바꿀 근거면 profile.md 「목표」의 이직 대전제 줄대로 알린다. 원인이 이 스킬의 규칙이면 [maintenance.md](maintenance.md)를 따른다.
- 지원 기준 점수를 바꾸자는 제안은 같은 패턴이 되풀이될 때 한다. 적용은 사용자가 승인한 뒤에, 프로필에 기록한다.

## 부족한 역량과 학습 계획

사용자가 원할 때 한다. 평가 보고서가 적으면 격차 목록이 우연일 수 있다고 함께 말한다.
- 점수가 낮은 공고일수록 격차를 더 많이 알려 준다고 보고, 점수가 낮은 공고에서 자주 나온 요건을 모은다. 격차마다 평가 몇 건 중 몇 건에서 나왔는지 쓴다.
- 프로필에 이미 있는 역량은 격차로 치지 않는다.
- 공부는 이미 가진 인접 역량에서 출발하게 한다. 선행 기술과 짧은 자료를 앞에 둔다.
- 격차마다 무료 자료 우선으로 2~3개를 찾는다. 무료 자료가 없으면 없다고 쓰고, 유료 자료로 말없이 바꾸지 않는다. 실제로 찾은 자료만, 소요 시간은 자료에 적힌 경우만 쓴다. 같은 격차를 되풀이해 검색하지 않는다.
